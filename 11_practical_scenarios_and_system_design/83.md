## 83. Scenario: The model gives great answers in testing but hallucinates intermittently in production. How do you debug it?

### Answer

This is one of the most common and dangerous failure modes in enterprise AI engineering: the **"Works in the Playground, Breaks in Production"** dilemma. 

When a model transitions from a controlled laboratory evaluation into live production, it is exposed to unbounded human variability, complex real-time retrieval data, and stochastic edge cases.

Debugging intermittent production hallucinations requires a disciplined, hypothesis-driven forensic methodology.

### The 5 Root Causes of the Testing-to-Production Divergence

#### 1. Input Distribution Shift & Lexical Variance
- **Testing:** Test cases were authored by engineers who formulated grammatically clear, well-structured, and polite prompts.
- **Production:** Real end users enter fragmented, ambiguous, misspelled queries with domain slang (e.g., *"charge on card bad Oct 4 refund now"*). The LLM's attention heads fail to anchor on ambiguous entities, triggering speculative next-token continuations.

#### 2. The "Lost in the Middle" Retrieval Phenomenon
- **Testing:** Developers tested the system using 1 or 2 small, clean mock documentation chunks.
- **Production:** The live vector database retrieved 10 lengthy chunks ($5,000+$ tokens) containing outdated product FAQs, boilerplate legal disclaimers, and conflicting policy revisions. Because Transformer attention forms a U-curve, critical facts located in the middle of the context window were neglected by the self-attention heads.

#### 3. Stochastic Sampling Misconfiguration
- **Testing:** The developer tested in an interactive UI with temperature set to $0.0$ or $0.2$.
- **Production:** The production configuration file omitted temperature, causing the SDK to default to $T = 0.7$ or $1.0$. At $T = 1.0$, improbable tokens in the tail occasionally get sampled, causing sporadic hallucinations on identical inputs!

#### 4. Delimiter Escaping & Instruction Confusion
- User input contained quotes, Markdown code fences, or colons that unintentionally escaped naive string interpolation (`f"Context: {context}\nQuestion: {query}"`), causing the model to interpret user text as system instructions.

#### 5. Parametric Memory Conflict (Base Model vs. RAG Conflict)
- If retrieved context states *"Widget X costs $400"*, but the foundation model's pretraining data memorized that *"Widget X costs $250"*, the model experiences attention conflict. Under stochastic sampling, the stronger parametric prior will occasionally override the retrieved context!

### Systematic 5-Step Remediation Playbook

#### Step 1: Trace Extraction and Forensic Replay
1. Navigate to the observability dashboard (Langfuse) and look up the exact **Trace ID** of the hallucinated session.
2. Extract the **exact synthesized prompt string**, retrieved chunks, model snapshot ID, temperature, and top-p.
3. Replay the request locally in a Python script at $T = 0.0$. If the error reproduces deterministically, the issue is structural; if it disappears, the issue is stochastic temperature sampling.

#### Step 2: Enforce Strict Deterministic Decoding
For factual tasks (QA, extraction, summarization), lock down sampling:
- Set `temperature = 0.0`.
- If creative flexibility is needed, enforce `temperature = 0.2` with `top_p = 0.90` and a `presence_penalty = 0.0`.

#### Step 3: Sanitize and Prune RAG Context (Context Hygiene)
- **Implement Cross-Encoder Re-Ranking:** Never dump 10 raw vector chunks into context. Pass the top-20 candidates through a cross-encoder (e.g., `Cohere Rerank` or `BGE-Reranker-Large`) and feed **only the top-3 highest-scoring chunks** to the LLM.
- **Context Ordering:** Place the most critical retrieved chunks at the **very top** and **very bottom** of the context, avoiding the middle attention trough.

#### Step 4: Structural Delimitation & Negative Constraints
Re-architect the prompt using unambiguous XML delimiters and strict negative fallback rules:

```xml
<context>
{reranked_chunks}
</context>

<instructions>
1. Answer the question in <query> relying STRICTLY on verified facts inside <context>.
2. If the context does not explicitly provide the answer, respond EXACTLY with:
   "I cannot verify this information based on available documentation."
3. Every factual assertion MUST include a citation tag referencing the source chunk: [Source: DocumentName].
4. Never extrapolate or assume facts not explicitly stated in <context>.
</instructions>

<query>
{sanitized_user_query}
</query>
```

#### Step 5: Regression Canary Locking
Never let an incident pass without automated protection:
1. Scrub PII from the failed production query.
2. Add the query, context, and ground-truth answer to the **Offline Golden Evaluation Benchmark**.
3. Incorporate the test into GitHub Actions CI/CD to prevent future prompt modifications from re-introducing the hallucination.

---

### Key Point

> **Intermittent production hallucinations stem from distributional shift, context bloat ("Lost in the Middle"), stochastic temperature defaults, or delimiter escaping. Debugging requires trace extraction, deterministic replay at $T=0.0$, context pruning via cross-encoder re-ranking, XML delimitation with citation requirements, and regression test locking.**

### Interview Answer

> "When an LLM behaves well in testing but hallucinates intermittently in production, I execute a structured five-step triage:
> 
> 1. **Trace Isolation & Deterministic Replay:** Using our observability platform (Langfuse), I pull the exact Trace ID to inspect the full prompt payload, retrieved context, and hyperparameters. I replay the exact request locally at `temperature = 0.0` to determine whether the hallucination is structural or driven by high sampling temperature.
> 2. **Context Forensics & 'Lost in the Middle':** In production RAG, retrieving too many chunks often buries critical facts in the middle of long contexts where attention degrades. I inspect whether retrieved chunks were noisy, conflicting, or outdated.
> 3. **Context Pruning via Re-Ranking:** I implement a Cross-Encoder Re-Ranker (like Cohere or BGE) to prune retrieved chunks from 10 down to the top-3 most relevant, placing critical facts at the beginning and end of the prompt.
> 4. **Prompt Hardening:** I wrap inputs in XML tags, mandate source citations for every claim, and provide an explicit fallback directive (*'If not in context, state you cannot verify'*).
> 5. **CI/CD Regression Locking:** I sanitize the failure case and permanently add it to our automated offline evaluation test suite to guarantee the regression never recurs."
