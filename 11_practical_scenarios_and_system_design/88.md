## 88. System Design: Design a production enterprise support assistant.

### Answer

Designing an enterprise customer support assistant requires building a mission-critical, multi-tenant distributed system capable of handling **50,000+ daily queries**, answering complex policy questions, querying internal databases, executing restricted operational actions (e.g., initiating refunds), and escalating seamlessly to human agents.

### Core System Requirements

#### Functional Requirements
1. **Policy & FAQ Question Answering:** Grounded in enterprise documentation with verifiable source citations.
2. **Account Personalization:** Retrieves customer order history, active subscriptions, and shipment tracking.
3. **Autonomous Operational Actions:** Executes low-risk operations (e.g., resending receipt, resetting password, issuing refunds $\le \$50$) via authenticated internal APIs.
4. **Human Agent Escalation:** Detects user frustration or high-risk requests, passes full conversational state, and hands off to live support agents in Zendesk/Salesforce.

#### Non-Functional Requirements
- **Latency SLA:** Time to First Token (TTFT) $< 500\text{ms}$; Inter-Token Latency (ITL) $< 40\text{ms}$.
- **Security & PII:** Zero leakage of Personally Identifiable Information (PII); immune to prompt injection.
- **Availability:** 99.99% uptime with automated provider failover.

---

### Detailed Component Deep Dive

#### 1. Perimeter Security & PII Masking
Before user text ever reaches the LLM or vector database:
- **PII Scrubbing (Presidio):** Replaces credit card numbers, phone numbers, and Social Security numbers with generic tokens (`[CREDIT_CARD_1]`).
- **Input Guardrail (Llama Guard):** Classifies the query for adversarial jailbreaks or prompt injections. Malicious requests are rejected immediately at the gateway layer.

#### 2. Hybrid RAG Subsystem with Tenant-Level Access Control (ACLs)
- **Document Chunking:** Support articles are parsed into 500-token chunks with 50-token overlaps.
- **Hybrid Retrieval:** Dense embeddings (vector search) capture semantic meaning, while sparse BM25 indices capture exact part numbers, error codes, and alphanumeric policy IDs.
- **Tenant Filtering:** Vector queries enforce metadata filters (`tenant_id == user.tenant_id`) ensuring strict data isolation across enterprise clients.
- **Cross-Encoder Re-Ranking:** Prunes the top-20 retrieved chunks down to the top-3 highest-relevance passages.

#### 3. Action Dispatcher: Safe Autonomous Tool Calling
When the LLM decides to execute an action (e.g., `refund_transaction`):
1. **Schema Validation:** The tool call arguments are parsed against a Pydantic schema.
2. **Policy Enforcement Engine (Guardrail):**
   - The application checks: `if action == "refund" and amount > 50.00: trigger_human_escalation()`.
   - Actions strictly obey the principle of least privilege.
3. **Idempotency Keys:** Every external API request contains a UUID idempotency key (`idempotency_key = hash(session_id, transaction_id)`) ensuring network retries never trigger duplicate financial charges!

#### 4. The Human Escalation Handover Protocol
If the customer expresses anger, or if the conversation exceeds 3 failed attempts:
1. The assistant states: *"I am connecting you with a senior human specialist right now."*
2. A background task runs a fast summarization prompt:
   ```text
   Summarize this chat session in 3 bullet points:
   - Primary Customer Problem:
   - Actions Attempted by Bot:
   - Reason for Escalation:
   ```
3. The summary and full conversation transcript are injected directly into the live agent's Zendesk/Salesforce dashboard.

### Key Point

> **An enterprise support assistant system design pairs an API gateway and Presidio PII scrubber with a hybrid RAG pipeline, a multi-tenant vector database, an idempotent action dispatcher with strict financial guardrails, and an automated summarization queue for human escalation.**

### Interview Answer

> "To design a production enterprise support assistant handling 50,000 daily queries, I architect a secure, multi-tier distributed system:
> 
> 1. **Perimeter Defense & PII:** Inbound traffic passes through an API gateway running Microsoft Presidio to scrub PII and Llama Guard to block prompt injections in $<20\text{ms}$.
> 2. **Hybrid RAG Context:** We retrieve support policies via hybrid search (Qdrant dense vectors + BM25 keyword matching) with tenant-level metadata filtering, refined through a Cohere cross-encoder re-ranker.
> 3. **State & Orchestration:** Dialogue history is maintained in Redis using a sliding window. The core reasoning agent (orchestrated via FastAPI and LiteLLM) executes structured tool calling using strict Pydantic schemas.
> 4. **Defensive Action Execution:** Operational tools (e.g., issuing refunds) enforce programmatic hard constraints (e.g., max $\$50$ refund cap) and utilize distributed idempotency keys to prevent duplicate actions.
> 5. **Human Escalation:** Frustrated users or complex inquiries automatically trigger an escalation worker that synthesizes a 3-bullet handoff summary into the live agent's CRM queue."
