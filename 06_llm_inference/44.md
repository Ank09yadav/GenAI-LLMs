## 44. What are logits?

### Answer

In Large Language Models, **logits** are the raw, unnormalized, real-valued score vectors produced by the model's final linear projection layer (the **unembedding layer**) prior to probability normalization.

For a vocabulary of size $|V|$ (e.g., 128,256 tokens in LLaMA-3), the model outputs a logit vector $\mathbf{z} \in \mathbb{R}^{|V|}$ where each scalar $z_i \in (-\infty, +\infty)$ reflects the model's unnormalized confidence that vocabulary token $i$ is the correct continuation of the preceding context.

```text
                           The Birth of Logits in a Transformer
                           
 Final Hidden State Vector:
 h_t ∈ R^{d_model} (e.g., d = 4,096)
          │
          ▼
 ┌────────────────────────────────────────────────────────┐
 │ Unembedding Linear Head (Matrix W_u ∈ R^{|V| x d})     │
 │ z = W_u · h_t + b                                      │
 └────────────────────────┬───────────────────────────────┘
                          │ Raw Logit Vector z ∈ R^{128,256}
                          ▼
            Token:        Logit Score (z_i):
            "Paris"   ──►  +14.82
            "Lyon"    ──►  +9.31
            "the"     ──►  +5.10
            "banana"  ──►  -8.45
                          │
                          ▼ Softmax Normalization P(v) = exp(z_v) / Σ exp(z_j)
            Token:        Normalized Probability:
            "Paris"   ──►  0.9959
            "Lyon"    ──►  0.0039
            "the"     ──►  0.0001
            "banana"  ──►  0.0000
```

### Mathematical Transformation: From Logits to Probabilities

To convert unconstrained real numbers into a valid probability distribution where all values satisfy $P(v_i) \in [0, 1]$ and $\sum P(v_i) = 1$, the model applies the **Softmax function**:

$$P(v_i) = \frac{\exp(z_i)}{\sum_{j=1}^{|V|} \exp(z_j)}$$

#### The Numerical Stability Problem: The "Safe Softmax" Trick
In 16-bit floating-point arithmetic (FP16 or BF16), numerical overflow occurs if any intermediate value exceeds $65,504$. If a logit $z_i = 90$, calculating $\exp(90) \approx 1.22 \times 10^{39}$, triggering an immediate **NaN (Not a Number)** crash.

To prevent overflow, production inference engines implement the mathematically equivalent **Safe Softmax**:

$$z_i' = z_i - \max_{k \in V}(z_k)$$

$$P(v_i) = \frac{\exp(z_i')}{\sum_{j=1}^{|V|} \exp(z_j')}$$

Because the maximum value of $z_i'$ is strictly $0$, $\exp(z_i') \le 1.0$, guaranteeing that exponentiation **never overflows**.

### Logit Engineering: How Runtime Sampling Modifies Logits

Logits are the central control surface for steering LLM generation at inference. Almost every sampling parameter directly mutates the logit vector **before** softmax is evaluated:

```text
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ 1. Temperature Scaling: z_scaled = z / T                                    │
 │ Divides logits by scalar T. Sharpens (T < 1) or flattens (T > 1) entropy.   │
 ├─────────────────────────────────────────────────────────────────────────────┤
 │ 2. Frequency & Presence Penalties                                           │
 │ Penalizes repetitive tokens: z_i ← z_i - (α_freq * count) - (α_pres * seen) │
 ├─────────────────────────────────────────────────────────────────────────────┤
 │ 3. Logit Bias (Token Forcing / Banning)                                     │
 │ User-defined offsets: Adding -100 completely bans a token (z_i = -∞).       │
 ├─────────────────────────────────────────────────────────────────────────────┤
 │ 4. Grammar-Constrained Logit Masking (FSMs)                                 │
 │ Sets z_i = -∞ for any token that violates a JSON Schema or regex grammar.   │
 ├─────────────────────────────────────────────────────────────────────────────┤
 │ 5. Top-K and Top-P Truncation                                               │
 │ Prunes low-ranked or tail tokens by setting their logits to -∞.             │
 └─────────────────────────────────────────────────────────────────────────────┘
```

---

### Frequency and Presence Penalty Equations

When configuring APIs (OpenAI, Anthropic, vLLM), developers use penalties to prevent repetitive loops:

$$z_i \leftarrow z_i - \left( c_i \cdot \alpha_{\text{frequency}} \right) - \left( \mathbb{I}(c_i > 0) \cdot \alpha_{\text{presence}} \right)$$

Where:
- $c_i$ is the number of times token $i$ has already appeared in the current generation.
- $\mathbb{I}(c_i > 0)$ is an indicator function returning $1$ if the token appeared at least once.
- $\alpha_{\text{frequency}}$ discounts tokens proportionally to their repetition.
- $\alpha_{\text{presence}}$ applies a flat one-time penalty for repeating any existing concept.

---

### Key Point

> **Logits are the raw, unnormalized scalar scores output by the final unembedding layer for every token in the vocabulary. They represent uncalibrated token affinities and serve as the primary mathematical surface manipulated by sampling parameters (temperature, penalties, logit bias, and grammar masks) prior to softmax normalization.**

---

### Interview Answer

> "Logits are the raw, unnormalized floating-point outputs generated by multiplying the final hidden state of the Transformer by the unembedding matrix $W_u$, resulting in a vector spanning the entire vocabulary size $|V|$.
> 
> Logits represent unnormalized log-odds. Applying the softmax function transforms them into a valid probability distribution. In production inference, calculating softmax naively in FP16 causes numerical overflow, so engines use 'Safe Softmax' by subtracting the maximum logit before exponentiation. 
> 
> Furthermore, logits are the runtime intervention point for all decoding controls: temperature scales them, presence and frequency penalties subtract repetition costs, logit biases force or forbid specific words, and grammar-constrained engines mask invalid syntax tokens to $-\infty$."
