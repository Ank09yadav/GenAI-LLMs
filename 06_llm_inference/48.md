## 48. What is greedy decoding?

### Answer

**Greedy Decoding** is the simplest, most computationally direct, and fully deterministic text generation strategy. At each autoregressive step $t$, greedy decoding selects the single token that maximizes the conditional probability distribution—equivalent to taking the **argmax** of the raw logit scores:

$$x_t = \arg\max_{v \in V} P(x_t = v \mid x_{<t}) = \arg\max_{v \in V} z_{t, v}$$

Because it involves no random sampling, greedy decoding yields identical, reproducible outputs on every execution. It is mathematically equivalent to setting **Temperature $T \to 0$** or **Top-K $= 1$**.

```text
                               Greedy Decoding Step
                               
 Logits at Step t:
 ┌────────────────────────────────────────────────────────┐
 │ Token:     Logit (z_i)     Softmax Prob P(v_i)         │
 │ "Paris"    +14.2           0.824  ◄── ARGMAX (SELECTED)│
 │ "Lyon"     +11.8           0.125                       │
 │ "Rome"     +9.4            0.041                       │
 │ "Berlin"   +6.1            0.010                       │
 └────────────────────────────────────────────────────────┘
                   No random sampling. Highest score ALWAYS wins!
```

---

### The Fundamental Flaw: The Myopic Local Optima Trap

The fatal theoretical limitation of greedy decoding is that it is **myopic (short-sighted)**: it optimizes each token locally without any foresight regarding the long-term sequence likelihood.

Mathematically, the sequence with the highest joint probability over $T$ tokens is **not** necessarily composed of the individual argmax tokens:

$$\max_{X} \prod_{t=1}^{T} P(x_t \mid x_{<t}) \neq \prod_{t=1}^{T} \max_{x_t} P(x_t \mid x_{<t})$$

```text
                       The Greedy Local Optima Blindspot
                       
                      Start: "The"
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
     "dog" (P = 0.55)            "animal" (P = 0.45)  ◄── Greedy picks "dog" (0.55 > 0.45)
             │                           │
             ▼                           ▼
     "barked" (P = 0.08)         "roared" (P = 0.90)
             │                           │
             ▼                           ▼
 Path A (Greedy Choice):     Path B (Globally Superior Path):
 0.55 * 0.08 = 0.044         0.45 * 0.90 = 0.405  (10x HIGHER GLOBAL PROBABILITY!)
```

By choosing the locally greedy token `"dog"`, the model permanently blinds itself to the globally superior sentence path initiated by `"animal"`.

---

### Failure Modes in Open-Ended Text Generation

1. **Repetitive Degeneration Loops:** In creative or long-form writing, greedy decoding frequently traps the model in self-reinforcing cyclic loops:
   > *"The company reported strong growth, and the company reported strong growth, and the company reported..."*  
   Because the model selects the highest logit, and prior tokens reinforce the same semantic state, the argmax becomes trapped in an infinite cycle.
2. **Bland, Monotone Phrasing:** Greedy decoding systematically strips out creative idioms, nuanced metaphors, and diverse sentence structures, producing flat, robotic prose.

---

### Greedy Decoding vs. Beam Search vs. Stochastic Sampling

| Strategy | Search Type | Deterministic? | Failure Mode | Optimal Use Case |
| :--- | :--- | :--- | :--- | :--- |
| **Greedy Decoding** | Local 1-step argmax | **Yes** | Repetitive loops, sub-optimal paths | Deterministic tasks (SQL, JSON, Code, Math) |
| **Beam Search ($B > 1$)** | Global heuristic tree search | **Yes** | Computationally heavy; robotic open-ended text | Translation, abstractive document summarization |
| **Nucleus Sampling (Top-P)**| Stochastic dynamic truncation | No (Randomized) | Occasional hallucinations | Creative writing, conversational chat, brainstorming |

---

### When to Use Greedy Decoding in Production

Greedy decoding is the industry standard whenever **factual accuracy and structural correctness supersede creativity**:
- **Code & SQL Synthesis:** A misplaced bracket or hallucinated keyword breaks compilation.
- **Structured JSON/YAML Extraction:** The engine must follow strict syntax without deviation.
- **Mathematical & Symbolic Logic:** Multi-step arithmetic requires consistent, greedy chain-of-thought deductions.
- **Unit Testing & CI/CD Benchmarking:** Comparing model performance across PRs requires deterministic, reproducible outputs.

---

### Key Point

> **Greedy decoding selects the token with the highest conditional probability ($\arg\max$) at every step. While fully deterministic and optimal for code and JSON extraction, its myopic local optimization can trap generation in repetitive cycles and miss globally superior sentence paths.**

### Interview Answer

> "Greedy decoding is a deterministic generation algorithm where the model selects the vocabulary token with the highest logit score ($\arg\max$) at each autoregressive step, equivalent to setting temperature to 0.
> 
> Its primary advantage is total reproducibility, making it the industry standard for tasks requiring strict correctness like SQL generation, mathematical logic, and JSON parsing. 
> 
> However, greedy decoding suffers from a well-known theoretical flaw: it is myopic. Because it maximizes token probability locally at step $t$, it frequently misses globally optimal sequence paths that may start with a slightly lower probability token. Furthermore, in long-form creative text, greedy decoding is prone to degenerate repetition loops, which is why stochastic nucleus sampling (Top-P) is preferred for conversational chat."
