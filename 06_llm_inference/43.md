## 43. How does LLM inference work?

### Answer

Large Language Model (LLM) inference is the runtime execution process of passing a prompt into a trained neural network to generate output tokens autoregressively. 

Unlike standard neural network inference (e.g., ResNet classifying an image in a single pass), LLM inference is structurally divided into **two radically different computational phases**: the **Prefill Phase** and the **Decode Phase**.

```text
                               The Two Phases of LLM Inference
                               
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │ PHASE 1: PREFILL (Prompt Processing)                                                        │
 │ ─────────────────────────────────────────────────────────────────────────────────────────── │
 │ Input: Full user prompt [x_1, x_2, ..., x_N] (e.g., 2,048 tokens)                           │
 │ Computation: Fully Parallel Matrix-Matrix Multiplication (GEMM)                             │
 │ Bound: COMPUTE-BOUND (High Arithmetic Intensity; fully utilizes GPU Tensor Cores)           │
 │ Action: Computes hidden states and populates the KV Cache for all prompt tokens             │
 │ Key Metric: Time to First Token (TTFT)                                                      │
 └──────────────────────────────────────────────┬──────────────────────────────────────────────┘
                                                │
                                                ▼ Emits First Token
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │ PHASE 2: DECODE (Autoregressive Generation Loop)                                            │
 │ ─────────────────────────────────────────────────────────────────────────────────────────── │
 │ Input: Single new token x_{t} + Existing KV Cache history                                   │
 │ Computation: Sequential Matrix-Vector Multiplication (GEMV)                                 │
 │ Bound: MEMORY-BANDWIDTH BOUND (Low Arithmetic Intensity; reading weights dominates)        │
 │ Action: Appends 1 new K/V vector to cache; emits 1 new token; loops until <EOS> or max_tok  │
 │ Key Metric: Inter-Token Latency (ITL) / Time Per Output Token (TPOT)                        │
 └─────────────────────────────────────────────────────────────────────────────────────────────┘
```

---

### Phase 1: The Prefill Phase (Prompt Processing)

When a prompt enters an inference engine:
1. All $N$ prompt tokens are embedded simultaneously.
2. The model performs forward passes across all layers in parallel.
3. Attention is computed across the entire prompt sequence using causal masking.
4. **Key and Value vectors for all $N$ tokens are computed and stored in GPU High Bandwidth Memory (HBM)**—forming the **KV Cache**.
5. The model outputs a probability distribution for token $N+1$, samples the first generated token, and completes the prefill phase.
- **Hardware Profile:** High arithmetic intensity (FLOPs / byte). The GPU Tensor Cores operate at peak utilization.

---

### Phase 2: The Decode Phase (Autoregressive Step)

Once the first token is produced, the engine switches to the **Decode Phase**:
1. At step $t$, **only the single newest token** $x_t$ is passed through the network.
2. The network does not recompute past tokens. Instead, it reads the historical Keys and Values directly from the **KV Cache** in HBM.
3. The model computes the query vector $\mathbf{q}_t$, attends over the cached Keys and Values, projects through the Feed-Forward Network, and produces logits for token $x_{t+1}$.
4. Token $x_{t+1}$ is sampled and its Key and Value vectors are appended to the KV cache.
5. This cycle repeats sequentially until an `<end_of_sequence>` token is generated or the maximum context length is reached.
- **Hardware Profile:** Low arithmetic intensity. The GPU must load all tens of billions of model parameters from slow HBM into on-chip SRAM just to calculate a single token!

---

### Mathematical Latency Decomposition

Total end-to-end inference latency for a user request is expressed as:

$$\text{Latency}_{\text{total}} = \text{TTFT} + (N_{\text{out}} - 1) \times \text{ITL}$$

Where:
- $\text{TTFT}$ (Time to First Token) $\approx \frac{\text{FLOPs}_{\text{prefill}}}{\text{Peak GPU FLOPS}} + \text{Queue Delay}$
- $\text{ITL}$ (Inter-Token Latency) $\approx \frac{2 \times N_{\text{params}}}{\text{GPU Memory Bandwidth (Bytes/sec)}}$
- $N_{\text{out}}$ = Total number of generated completion tokens.

---

### Static Batching vs. Continuous / Iteration-Level Batching

In early serving frameworks, batched inference suffered from the **Straggler Problem**: if one request generated 500 tokens and another generated 10 tokens, the short request had to wait idle while the GPU finished the long request.

Modern engines (e.g., **vLLM**, **TGI**, **TensorRT-LLM**) utilize **Continuous Batching (Orca)**:

```text
 Continuous Batching (Iteration-Level Scheduling):
 Step 1: [Req A: Tok 1] [Req B: Tok 42] [Req C: Prefill]  ──► Emit tokens
 Step 2: [Req A: Tok 2] [Req B: <EOS> ] [Req C: Tok 1  ]  ──► Req B finishes immediately!
 Step 3: [Req A: Tok 3] [Req D: Prefill] [Req C: Tok 2 ]  ──► Req D inserted without waiting!
```

Continuous batching schedules requests at the iteration (single-token) level, yielding $5\times$ to $10\times$ higher serving throughput.

---

### Key Point

> **LLM inference is split into a parallel, compute-bound Prefill phase (generating TTFT and populating the KV cache) and a sequential, memory-bandwidth-bound Decode phase (generating ITL one token at a time). Serving engines optimize this using continuous batching to schedule tokens dynamically at each forward pass.**

---

### Interview Answer

> "LLM inference operates in two distinct phases:
> 1. **Prefill Phase:** The entire input prompt is processed concurrently in a single parallel forward pass. This is compute-bound, saturating GPU Tensor Cores with general matrix-matrix multiplications (GEMM), and produces the first output token (governing Time to First Token, or TTFT) while initializing the KV cache in VRAM.
> 2. **Decode Phase:** The model generates output tokens one by one autoregressively. This is memory-bandwidth bound because the GPU must stream billions of model parameter weights from High-Bandwidth Memory (HBM) into cache for every single token generated, governing Inter-Token Latency (ITL).
> 
> Production serving engines maximize GPU utilization by leveraging continuous iteration-level batching, evicting completed sequences immediately and scheduling new prompt prefills into active decode steps."
