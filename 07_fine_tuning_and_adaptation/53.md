## 53. What is PEFT (Parameter-Efficient Fine-Tuning)?

### Answer

**Parameter-Efficient Fine-Tuning (PEFT)** is an umbrella taxonomy of model adaptation techniques designed to customize massive Large Language Models by **freezing the vast majority ($\ge 99\%$) of pretrained weights** and optimizing only a tiny fraction ($< 1\%$) of additional or selected parameters.

PEFT emerged as a vital engineering necessity to overcome the prohibitive computational, memory, and storage costs of **Full Parameter Fine-Tuning**.

```text
                           The VRAM Reality: Full Fine-Tuning vs. PEFT
                           
 Full Fine-Tuning of a 70B Model (Adam Optimizer in FP16/FP32):
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ Weights (FP16):          140 GB                                             │
 │ Gradients (FP16):        140 GB                                             │
 │ Adam Optimizer (FP32):   840 GB (12 bytes/param: master weights + m + v)    │
 │ Activations & Cache:     ~100 GB                                            │
 │ TOTAL VRAM REQUIRED:    > 1,200 GB (Requires 16x 80GB H100 GPUs = $400,000+)│
 └─────────────────────────────────────────────────────────────────────────────┘
                                                VS
 PEFT (e.g., LoRA Rank 16):
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ Frozen Base Weights:     140 GB (or 35 GB if 4-bit quantized)               │
 │ Adapter Weights & Grads: < 1 GB                                             │
 │ Adam Optimizer States:   < 2 GB (Only tracks adapter parameters!)           │
 │ TOTAL VRAM REQUIRED:     ~40 - 150 GB (Runs on a SINGLE commodity GPU!)     │
 └─────────────────────────────────────────────────────────────────────────────┘
```

### The Three Major Families of PEFT

Research in parameter efficiency is systematically classified into three architectural paradigms:

```text
                                   The PEFT Taxonomy
                                   
             ┌─────────────────────────────┼─────────────────────────────┐
             ▼                             ▼                             ▼
     Additive Methods              Selective Methods             Reparameterization
     (Insert new weights)         (Train subset of weights)      (Decompose weight updates)
     
     - Bottleneck Adapters        - BitFit (Train biases only)   - LoRA (Low-Rank Adaptation)
     - Prefix Tuning              - Sparse Diff Pruning          - QLoRA (Quantized LoRA)
     - Prompt Tuning                                             - DoRA (Weight-Decomposed)
```

#### 1. Additive Methods
- **Bottleneck Adapters (Houlsby et al., 2019):** Inserts small feed-forward residual bottleneck layers immediately after attention and MLP blocks. Down-projects dimension $d \to r$, applies non-linearity, and up-projects $r \to d$.
- **Prompt Tuning (Lester et al., 2021):** Prepends a sequence of continuous, trainable "virtual token embeddings" to the prompt, keeping the entire Transformer frozen.
- **Prefix Tuning (Li & Liang, 2021):** Prepends trainable virtual Key and Value vectors directly to the self-attention mechanism at every Transformer layer.

#### 2. Selective Methods (BitFit)
- **BitFit (Zaken et al., 2021):** Freezes all weight matrices and trains **only the bias vectors ($\mathbf{b}$)** throughout the network. While it updates less than $0.1\%$ of parameters, it can match up to 90% of full fine-tuning performance on basic classification tasks.

#### 3. Reparameterization / Low-Rank Methods (LoRA & QLoRA)
- Instead of adding intermediate sequential layers (which introduce inference latency), low-rank reparameterization represents the weight update matrix $\Delta W$ as the product of two low-rank matrices: $\Delta W = B \cdot A$.

### The Operational Superpower: Multi-Tenant Serving

In enterprise production, the greatest operational breakthrough of PEFT is **Multi-Tenant Adapter Serving**:

```text
                             Multi-Tenant LoRA Serving in VRAM
                             
                                   Single GPU Memory (e.g., A100 80GB)
                     ┌─────────────────────────────────────────────────┐
                     │ Frozen Shared Base Model: LLaMA-3-70B (140 GB)   │
                     └────────────────────────┬────────────────────────┘
                                              │
                     ┌────────────────────────┴────────────────────────┐
                     ▼                                                 ▼
      ┌──────────────────────────────┐                  ┌──────────────────────────────┐
      │ Client A: Legal Adapter      │                  │ Client B: Medical Adapter    │
      │ Size: 40 MB (LoRA Weights)   │                  │ Size: 40 MB (LoRA Weights)   │
      └──────────────────────────────┘                  └──────────────────────────────┘
```

- In full fine-tuning, serving 100 enterprise customers with bespoke models requires hosting **100 independent 70B models**—costing tens of thousands of dollars per month in idle GPU clusters.
- With PEFT, a single base model is loaded once into GPU VRAM. When Client A submits a request, the server dynamically activates Client A's **40MB adapter** in microseconds, enabling seamless multi-tenant serving at negligible marginal cost!

### Comparative Summary

| Dimension | Full Parameter Fine-Tuning | Parameter-Efficient Fine-Tuning (PEFT) |
| :--- | :--- | :--- |
| **Parameters Updated** | $100\%$ (All 70B parameters) | $< 0.2\%$ (~50M parameters) |
| **Memory Footprint** | Extremely large (16-24 bytes / param) | Minimal (Base model + tiny adapter state) |
| **Hardware Required** | Multi-node GPU cluster with InfiniBand | Single workstation or single cloud GPU |
| **Storage per Fine-Tuned Model** | Full checkpoint file (~140 GB) | Adapter weights only (~30 MB – 100 MB) |
| **Catastrophic Forgetting Risk**| Severe | Minimal (pretrained base weights remain frozen) |
| **Inference Latency** | Baseline ($1\times$) | Zero latency overhead if weights are merged |

---

### Key Point

> **PEFT freezes over 99% of base model parameters and trains a tiny fraction of adapter weights. By eliminating the massive optimizer state memory required for full fine-tuning, PEFT slashes VRAM requirements by over 80%, prevents catastrophic forgetting, and enables high-density multi-tenant serving where hundreds of 50MB adapters share a single base model.**

### Interview Answer

> "Parameter-Efficient Fine-Tuning (PEFT) is a class of techniques designed to adapt Large Language Models while updating only a minute fraction (typically $<0.2\%$) of parameters.
> 
> Its primary motivation is overcoming the memory wall of full fine-tuning: training a 70B model with the Adam optimizer requires over 1.2 Terabytes of VRAM to store weights, gradients, and 32-bit optimizer momentum and variance states. PEFT freezes the foundation weights—eliminating the need to store optimizer states for the base model—and trains small additions like bottleneck adapters, prefixes, or low-rank matrices (LoRA).
> 
> Beyond democratizing training onto single GPUs, PEFT's biggest enterprise advantage is multi-tenant deployment: an inference engine can host a single 70B base model in VRAM and dynamically swap dozens of lightweight 50MB customer-specific adapters on a per-request basis with zero latency penalty."
