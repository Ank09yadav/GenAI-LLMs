## 56. What is full fine-tuning vs parameter-efficient fine-tuning?

### Answer

The architectural choice between **Full Fine-Tuning (FFT)** and **Parameter-Efficient Fine-Tuning (PEFT)** defines the balance between model plastic capacity, hardware infrastructure expense, risk of catastrophic forgetting, and operational deployment agility.

- **Full Fine-Tuning (FFT):** Updates **100% of all parameters** across every layer of the neural network during backpropagation.
- **Parameter-Efficient Fine-Tuning (PEFT / LoRA):** Freezes **$\ge 99\%$ of foundation weights** and restricts backpropagation updates strictly to small modular adapter matrices or specialized sub-layers.

```text
                           Full Fine-Tuning vs. PEFT (LoRA)
                           
 Full Fine-Tuning (Monolithic Weight Drift):
 ┌────────────────────────────────────────────────────────┐
 │ Base Model (W_0)  ──► Backprop updates ALL weights  ──► │ Checkpoint W_final (140 GB)
 │ 70 Billion Params     Adam tracks 1.2 TB of states      │ Completely new model file!
 └────────────────────────────────────────────────────────┘
 
 Parameter-Efficient Fine-Tuning (Modular Adaptation):
 ┌────────────────────────────────────────────────────────┐
 │ Base Model (W_0)  ──► FROZEN (Zero Weight Drift)       │
 │ 70 Billion Params     Zero base optimizer memory       │
 ├────────────────────────────────────────────────────────┤
 │ Parallel Adapter  ──► Updates ~50M params (0.07%)   ──► │ Modular Adapter (40 MB)
 │ (Matrices A & B)      Tracks tiny optimizer state      │ Plugs into frozen base!
 └────────────────────────────────────────────────────────┘
```

---

### In-Depth Dimensional Comparison

| Dimension | Full Fine-Tuning (FFT) | Parameter-Efficient Fine-Tuning (PEFT / LoRA) |
| :--- | :--- | :--- |
| **Trained Parameters** | **$100\%$** (All parameters updated) | **$< 0.2\%$** (Only adapter parameters updated) |
| **GPU Memory Footprint** | Extremely High (16–20 bytes/param: weights + grads + Adam states) | Low (Base weights + tiny optimizer state for adapters) |
| **Hardware Minimum (70B)** | Multi-node cluster (16x H100 80GB GPUs) | Single GPU workstation (1x A100 or 1x A6000 with QLoRA) |
| **Catastrophic Forgetting**| **High Risk:** Easily degrades general reasoning and math abilities | **Minimal:** Base weights remain frozen; preserves pretraining |
| **Storage per Model Variant**| Huge (e.g., 140 GB per checkpoint) | Negligible (e.g., 20 MB – 50 MB per adapter file) |
| **Multi-Tenant Serving** | Impossible without duplicate GPU instances for each model | **Native:** 1 base model serves hundreds of dynamic adapters |
| **Training Speed** | Slower (all gradients & states computed) | Faster (gradients computed for tiny subset of matrices) |
| **Inference Latency** | Baseline ($1\times$) | Identical ($1\times$) when adapter is merged into base |
| **Capacity for Radical Shift**| **Maximum:** Can learn radically new vocabularies or modalities | **Moderate:** Constrained by the expressive subspace of rank $r$ |

---

### When is Full Fine-Tuning Still Required?

Despite PEFT's overwhelming efficiency advantages, there are three production scenarios where **Full Fine-Tuning remains essential**:

1. **Extreme Domain Shift / Unseen Languages:**
   If you are adapting an English-centric base model to an unrepresented low-resource language (e.g., Swahili, Sanskrit) or machine-level binary assembly code, the fundamental features in the base weights must be rewritten. The low-rank subspace of PEFT is insufficient to represent massive structural shifts in syntax and grammar.
2. **Foundation Alignment (Building SFT Frontier Models):**
   When creating primary instruction models (such as Meta building LLaMA-3-Instruct from LLaMA-3-Base across 10 million diverse multi-task datasets), full fine-tuning is preferred to ensure that every attention head and MLP neuron is maximally aligned.
3. **Continued Pretraining (DAPT) on Massive Corpora:**
   Ingesting 50+ billion tokens of raw proprietary code or biomedical literature requires modifying the model's base factual representations across all layers.

---

### When is PEFT / LoRA the Superior Engineering Choice?

For **95% of enterprise AI use cases**, PEFT is the mathematically and operationally superior strategy:
- **Task Specialization:** Converting an instruction model to output strict legal contracts, custom JSON, or specialized classification labels.
- **Continuous Learning & Rapid Experimentation:** Data science teams can train and validate 10 different LoRA adapters in parallel on a single workstation in an afternoon.
- **Enterprise SaaS Multi-Tenancy:** Storing 500 custom enterprise models as 40MB adapter files in an S3 bucket instead of paying for 500 dedicated 140GB model deployments.

---

### Key Point

> **Full fine-tuning updates all parameters, demanding massive GPU clusters and risking catastrophic forgetting, but allows radical domain shifts. PEFT freezes foundation weights and trains lightweight adapters, reducing VRAM by >80%, enabling multi-tenant serving, and eliminating forgetting for task specialization.**

---

### Interview Answer

> "Full Fine-Tuning (FFT) updates all model parameters across every layer during backpropagation. While it provides the maximum plasticity necessary for drastic domain shifts (such as training on a completely new language or binary assembly), it is computationally prohibitive—requiring multi-node GPU clusters to store 16–20 bytes per parameter for weights, gradients, and 32-bit Adam optimizer states—and carries a high risk of catastrophic forgetting.
> 
> Parameter-Efficient Fine-Tuning (PEFT), primarily exemplified by LoRA, freezes the foundation weights and trains a small subset of parameters ($<0.2\%$). PEFT reduces VRAM requirements by over 80%, prevents catastrophic forgetting by preserving the base representation manifold, and enables high-density multi-tenant serving where hundreds of 40MB customer adapters can be dynamically hot-swapped over a single shared base model in VRAM."
