## 58. What are common failure modes in fine-tuning?

### Answer

Fine-tuning a Large Language Model is deceptively accessible via modern libraries (such as Hugging Face `trl`, `peft`, and Axolotl), but production fine-tuning runs frequently fail due to subtle mathematical, structural, and data quality flaws.

A disciplined engineering team must recognize the canonical failure modes, diagnose them via loss telemetry, and execute corrective mitigations.

### The 7 Canonical Failure Modes & Diagnostic Protocols

#### 1. Unmasked Prompt Tokens (The "Prompt Memorization" Bug)
- **The Bug:** Failing to set prompt token target labels to `-100` (PyTorch `ignore_index`).
- **The Impact:** The loss function penalizes the model for failing to predict the *user's* query tokens! The model wastes parameter capacity memorizing how users phrase questions instead of mastering the target response distribution.
- **Diagnostic:** Validation loss on prompt-heavy sequences remains abnormally high; model begins hallucinating user follow-ups in its own answers.
- **Remedy:** Ensure the data collator explicitly applies `DataCollatorForCompletionOnlyLM` to mask prompt tokens.

#### 2. Hallucination Amplification (The "Factual Fabrication" Trap)
- **The Bug:** Fine-tuning an 8B model on a dataset containing domain facts that were never present in its original pretraining corpus.
- **The Impact:** Because the base model lacks parametric memory of the entities, SFT forces the model to synthesize answers from scratch, **teaching it that fabricating plausible-sounding statements is the correct behavior**.
- **Diagnostic:** The fine-tuned model speaks with extreme, uncalibrated confidence while outputting completely fabricated facts.
- **Remedy:** Do not use fine-tuning as a knowledge base! Use RAG for factual grounding; restrict fine-tuning to style, structure, and formatting.

#### 3. Overfitting & Repetition Loops (Epoch Saturation)
- **The Bug:** Training for too many epochs ($> 3 - 5$ epochs) on small datasets ($< 2,000$ pairs).
- **The Impact:** The model memorizes exact training phrases verbatim. When deployed, small variations in user phrasing trigger degenerate repetition loops or verbatim recitation of training data.
- **Diagnostic:** Training loss plummets toward near zero ($< 0.1$), while out-of-sample validation loss shoots upward (the classical divergence gap).
- **Remedy:** Enforce early stopping based on validation loss; cap training at 1 to 2 epochs; introduce gradient noise or weight decay.

#### 4. Learning Rate Shock & Feature Destruction
- **The Bug:** Applying pretraining learning rates (e.g., $10^{-3}$ or $5 \times 10^{-4}$) to full fine-tuning.
- **The Impact:** Gradient updates are so massive that they destroy the delicate orthogonal representations formed during pretraining, resulting in immediate catastrophic forgetting or NaN loss spikes.
- **Remedy:** Use conservative learning rates:
  - Full Fine-Tuning: $5 \times 10^{-6}$ to $2 \times 10^{-5}$
  - LoRA / PEFT: $1 \times 10^{-4}$ to $2 \times 10^{-4}$
  - Always enforce linear warmup for the first 3% to 5% of training steps.

#### 5. Verbosity Bias & Style Drift
- **The Bug:** Curating training demonstrations where human annotators wrote unnecessarily long, verbose responses because long answers "felt" more thorough.
- **The Impact:** The model internalizes length as a proxy for quality. Simple inquiries receive 600-word essays filled with repetitive pleasantries and disclaimers.
- **Remedy:** Filter training completions by word count; aggressively prune conversational filler during data curation.

#### 6. Loss Spikes & Mixed-Precision Underflow (FP16 vs. BF16)
- **The Bug:** Training large models in traditional FP16 without properly calibrated dynamic loss scaling.
- **The Impact:** Exponent overflow (values $> 65,504$) or underflow triggers sudden `NaN` losses, permanently corrupting model weights mid-run.
- **Remedy:** Train exclusively in **BF16** (Bfloat16), which shares the exact same 8-bit dynamic exponent range as FP32, eliminating underflow/overflow spikes.

#### 7. Benchmark Leakage (Evaluation Contamination)
- **The Bug:** Inadvertently scraping public benchmark questions (e.g., MMLU, GSM8K, HumanEval) into the fine-tuning mixture.
- **The Impact:** The model scores 98% on academic benchmarks, but completely collapses on real-world customer production queries.
- **Remedy:** Execute automated $n$-gram decontamination checks between training corpora and evaluation benchmarks.

### Diagnostic Troubleshooting Matrix

| Observed Symptom | Primary Suspect | Production Action |
| :--- | :--- | :--- |
| **Model repeats boilerplate words endlessly** | Overfitting / Too many epochs | Halt training; roll back to epoch 1 checkpoint; increase dropout. |
| **Validation loss diverges after epoch 2** | Overfitting on small dataset | Implement early stopping; add 20% general replay data. |
| **Model hallucinates confident falsehoods** | SFT forcing knowledge injection | Switch to RAG architecture; prune ungrounded pairs from dataset. |
| **Loss suddenly spikes to NaN** | FP16 overflow / High learning rate | Switch precision to BF16; reduce learning rate; clip gradients to $1.0$. |
| **General reasoning and coding plunge** | Catastrophic forgetting | Switch from Full Fine-Tuning to LoRA; blend in 15% replay data. |

---

### Key Point

> **The primary failure modes in fine-tuning are unmasked prompt tokens, hallucination amplification from forced knowledge injection, overfitting on small datasets, learning rate shock destroying pretrained weights, and verbosity bias. Successful fine-tuning requires BF16 precision, completion-only loss masking, strict validation loss tracking, and canary benchmark evaluation.**

### Interview Answer

> "The most common failure modes in fine-tuning span data engineering, optimization stability, and behavioral degradation:
> 1. **Data Misconfigurations:** Forgetting to mask prompt tokens (allowing loss to compute on user prompts instead of strictly on completions) and dataset contamination with benchmark test sets.
> 2. **Knowledge Injection Hallucinations:** Attempting to teach an LLM new facts via SFT rather than RAG, which trains the model to fabricate plausible falsehoods with high confidence.
> 3. **Optimization Failures:** Using overly aggressive learning rates that destroy pretrained representations, or using FP16 instead of BF16, leading to NaN gradient explosions.
> 4. **Overfitting & Verbosity Bias:** Training for more than 2–3 epochs on small datasets, causing the model to memorize phrases verbatim and exhibit severe repetition loops.
> 5. **Catastrophic Forgetting:** Overwriting base reasoning capabilities by failing to include 15–20% general replay data in the training blend."
