## 64. How do you evaluate RAG systems?

### Answer

Evaluating a **Retrieval-Augmented Generation (RAG)** pipeline is significantly more intricate than evaluating a standalone LLM because a RAG system consists of **two distinct, coupled subsystems**: the **Retriever** (vector search, keyword BM25, re-ranking) and the **Generator** (the LLM synthesizing the response).

If a RAG system outputs an incorrect response, engineers must determine whether:
- The **Retriever failed** by pulling irrelevant chunks (Garbage In).
- The **Generator failed** by hallucinating despite receiving the correct chunks (Garbage Out).

To diagnose and isolate these failures, the industry standard is the **RAG Triad** (formalized by TruLens and Ragas).

```text
                                     The RAG Triad
                                     
                                    [ User Query ]
                                          ▲
                                         / \
                                        /   \
                     1. Context        /     \   3. Answer
                        Relevance     /       \     Relevance
                                     /         \
                                    ▼           ▼
                         [ Retrieved ] ───────► [ Generated ]
                         [  Context  ]          [ Response  ]
                                       2. Groundedness
                                       (Faithfulness)
```

---

### The Three Edges of the RAG Triad

#### 1. Context Relevance (Retriever Quality)
- **What it Evaluates:** Measures how pertinent and noise-free the retrieved text chunks are with respect to the user's prompt.
- **Why it Matters:** Ingesting 20 irrelevant chunks pollutes the context window, triggers the "Lost in the Middle" phenomenon, and spikes API token costs.
- **Classical Information Retrieval Metrics:**
  - **Precision@K:** Proportion of retrieved chunks that are relevant.
  - **Recall@K:** Proportion of all relevant chunks that were successfully retrieved.
  - **Mean Reciprocal Rank (MRR):** How high up in the list the first relevant chunk appears.
  - **NDCG (Normalized Discounted Cumulative Gain):** Rewards placing the most relevant chunks at the very top of the ranking.

#### 2. Groundedness / Faithfulness (Generator Reliability)
- **What it Evaluates:** Measures whether every claim in the generated response can be mathematically or logically entailed from the **retrieved context alone**.
- **The Metric:**
  $$\text{Faithfulness} = \frac{\text{Number of Claims Supported by Retrieved Chunks}}{\text{Total Claims in Response}}$$
- **Significance:** A score of $1.0$ guarantees that the generator has not hallucinated ungrounded external assumptions.

#### 3. Answer Relevance (Task Fulfillment)
- **What it Evaluates:** Measures whether the final response directly addresses the user's specific request, regardless of whether it was grounded in context.
- **The Metric:** Evaluated via embedding cosine similarity between the user's prompt and a synthetic question reverse-engineered from the model's output, or scored on a 1-5 rubric by an LLM judge.

---

### RAG Failure Diagnosis Matrix

By evaluating all three edges independently, engineers can pinpoint exact architectural bottlenecks:

| Context Relevance | Groundedness | Answer Relevance | Diagnostic Diagnosis & Root Cause | Production Remedy |
| :---: | :---: | :---: | :--- | :--- |
| **Low** | High | Low | **Retriever Failure:** Inappropriate chunking or weak embeddings returned irrelevant context; generator did its best with bad data. | Upgrade embedding model; add Cross-Encoder Re-ranker; tune chunk overlap. |
| **High** | **Low** | High | **Generator Hallucination:** Perfect context retrieved, but model hallucinated ungrounded claims. | Enforce stricter system prompt constraints; lower temperature to $0.0$; use structured schemas. |
| **High** | High | **Low** | **Instruction Failure:** Model faithfully summarized retrieved docs, but didn't actually answer the prompt's question. | Improve system prompt; inject few-shot exemplars demonstrating direct answers. |
| **High** | **High** | **High** | **Optimal Pipeline:** Flawless retrieval, zero hallucination, direct prompt resolution. | Approved for production deployment. |

### Synthetic Evaluation: Automating the Test Set

Manual curation of RAG test sets (question-answer-context triplets) is painfully slow. Modern production frameworks (such as **Ragas** and **Ares**) automate benchmark creation:

```text
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ Raw Enterprise Knowledge Base (10,000 PDFs / Confluence Docs)               │
 └──────────────────────────────────────┬──────────────────────────────────────┘
                                        │ Chunking
                                        ▼
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ LLM Synthetic Generator:                                                    │
 │ Ingests chunk and generates:                                                │
 │ 1. Seed Question: "What is the deductible under Plan B?"                    │
 │ 2. Reasoning Question (Multi-hop): "Compare deductibles between Plan A & B"│
 │ 3. Ground-Truth Verified Answer directly extracted from text               │
 └──────────────────────────────────────┬──────────────────────────────────────┘
                                        │
                                        ▼
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ Automated Golden Benchmark Dataset (500 High-Quality Triplets)              │
 └─────────────────────────────────────────────────────────────────────────────┘
```

Every PR that touches chunk sizes, embedding models, vector distance metrics, or system prompts is automatically executed against this synthetic benchmark.

---

### Key Point

> **RAG evaluation isolates the Retriever from the Generator using the RAG Triad: Context Relevance (Retriever precision), Groundedness/Faithfulness (Generator hallucination check), and Answer Relevance (prompt fulfillment). Decoupling these dimensions pinpoints whether failures stem from vector search or model synthesis.**

---

### Interview Answer

> "Evaluating a RAG system requires decoupling the performance of the **Retriever** from the **Generator** using the industry-standard **RAG Triad**:
> 1. **Context Relevance:** Evaluates the retriever. Does the retrieved context contain the precise facts needed to answer the query without excessive noise? Measured via MRR, NDCG, and LLM-assessed relevance.
> 2. **Groundedness (Faithfulness):** Evaluates the generator. Is every factual claim in the generated answer strictly supported by the retrieved chunks? Measured as the ratio of entailed atomic claims to total claims.
> 3. **Answer Relevance:** Evaluates task fulfillment. Does the generated response directly resolve the user's inquiry without topic drift?
> 
> By scoring these three axes independently, we can diagnose whether a failure is due to bad embedding retrieval (low context relevance) or generator hallucination (low faithfulness), allowing targeted optimizations like re-ranking or prompt refinement."
