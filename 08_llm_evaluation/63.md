## 63. How do you evaluate factuality and hallucination?

### Answer

Evaluating **factuality** and detecting **hallucinations** is the most critical reliability discipline in enterprise Generative AI. 

Because LLMs optimize for next-token statistical likelihood rather than ontological truth, they generate text that is linguistically fluent, persuasive, and grammatically flawless—yet completely fabricated.

Modern evaluation divides hallucination assessment into two distinct operating regimes:
1. **Closed-Domain Faithfulness (Groundedness):** Evaluates whether generated statements are strictly derived from and supported by an **explicit reference context** (standard in RAG, search-augmented agents, and document summarization).
2. **Open-Domain Parametric Truthfulness:** Evaluates whether statements match **real-world objective facts** stored within the model's internal memory (world knowledge recall).

```text
                           The Atomic Claim Verification Pipeline
                           
 Candidate Model Output:
 "Marie Curie was born in Warsaw, Poland in 1867 and discovered Uranium in 1898."
                                    │
                                    ▼ STEP 1: Atomic Claim Decomposition
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ Claim 1: "Marie Curie was born in Warsaw."               ──► [SUPPORTED]     │
 │ Claim 2: "Warsaw is located in Poland."                 ──► [SUPPORTED]     │
 │ Claim 3: "Marie Curie was born in 1867."                ──► [SUPPORTED]     │
 │ Claim 4: "Marie Curie discovered Uranium in 1898."      ──► [HALLUCINATED!] │
 │           (Uranium was discovered by Klaproth in 1789;  │ (Unsupported)     │
 │            Curie discovered Radium and Polonium!)       │                   │
 └─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼ STEP 2: Mathematical Factuality Score
          Factuality (FActScore) = 3 Supported / 4 Claims = 75.0%
```

### The 4 Core Methodologies for Factuality Evaluation

#### 1. Atomic Claim Decomposition (FActScore, Min et al., 2023)
Traditional whole-sentence evaluation fails because a sentence is rarely 100% false; it is usually 90% true with one fabricated entity.
- **Algorithm:**
  1. Pass the generated text through an extraction model to decompose it into independent, non-decomposable **atomic propositions**.
  2. Each atomic proposition is independently evaluated against a verified ground-truth knowledge source (e.g., Wikipedia API or corporate database).
  3. Calculate the percentage of verified claims:
     $$\text{FActScore} = \frac{\sum_{i=1}^{M} \mathbb{I}(\text{Claim}_i \text{ is Supported})}{M}$$

#### 2. Natural Language Inference (NLI) Cross-Encoders
In closed-domain systems (RAG), factuality can be measured algorithmically using specialized **Natural Language Inference (NLI)** models without calling expensive LLM APIs:
- The retrieved document serves as the **Premise ($P$)**.
- The model's generated output serves as the **Hypothesis ($H$)**.
- An NLI model (such as `DeBERTa-v3-large` fine-tuned on MNLI) computes conditional probabilities across three states:
  $$P(\text{Entailment} \mid P, H) \quad P(\text{Neutral} \mid P, H) \quad P(\text{Contradiction} \mid P, H)$$
- If $P(\text{Neutral}) + P(\text{Contradiction}) > \tau$, the generation is flagged as an ungrounded hallucination.

#### 3. LLM-as-a-Judge Faithfulness (Ragas / TruLens Frameworks)
In production RAG evaluation, a frontier judge LLM evaluates **Faithfulness**:
- **Prompt:** *"Given the context below, identify every claim in the response that cannot be directly deduced from the context. Output the unsupported claims and assign a score from 0.0 to 1.0."*

#### 4. Stochastic Consistency Sampling (SelfCheckGPT, Manakul et al., 2023)
When evaluating open-domain factuality without access to an external reference database:
1. Sample $N = 10$ stochastic completions from the candidate model with high temperature ($T = 0.8$).
2. **The Core Intuition:** If the model genuinely "knows" a parametric fact, stochastic samples will consistently repeat that fact. If the model is hallucinating, random noise will cause different samples to contradict one another!
3. Measure the semantic divergence across samples to calculate a hallucination probability score.

---

### Key Point

> **Factuality evaluation measures parametric truth in open domains and contextual faithfulness in closed domains. It is quantified by decomposing sentences into atomic claims (FActScore), evaluating premise-hypothesis entailment via NLI cross-encoders, or detecting cross-sample contradictions via SelfCheckGPT.**

---

### Interview Answer

> "Evaluating factuality and hallucination requires distinguishing between **open-domain world truth** and **closed-domain faithfulness (groundedness)**.
> 
> In production RAG systems, closed-domain evaluation is dominant and typically implemented via **Atomic Claim Decomposition (FActScore)** or **NLI Cross-Encoders (DeBERTa)**:
> 1. Sentences are decomposed into discrete, testable atomic claims.
> 2. Each claim is checked against the retrieved context to verify whether the premise strictly entails the hypothesis.
> 3. Faithfulness is scored as the ratio of supported claims to total claims.
> 
> For open-domain hallucination where no ground truth context exists, techniques like **SelfCheckGPT** sample multiple stochastic completions; if the model produces conflicting claims across runs, it signals low parametric certainty and high hallucination probability."
