## 5. What types of tasks can LLMs perform?

### Answer

Because Large Language Models are trained on massive, multimodal distributions of human knowledge and code, they operate as **general-purpose semantic reasoning and text compilation engines**. Rather than being bound to a single task schema, their capabilities span five foundational functional domains:

```text
                        The Five Enterprise LLM Task Domains
                                          │
     ┌───────────────────┬────────────────┼───────────────────┬───────────────────┐
     ▼                   ▼                ▼                   ▼                   ▼
[Linguistic Synthesis] [Info Extraction] [Code & Software]   [Multi-Step Logic]  [Agentic Tools]
- Summarization        - Entity (NER)    - Code writing      - Chain-of-Thought  - SQL execution
- Translation          - Structured JSON - Bug debugging     - Math deduction    - REST API calls
- Tone rewriting       - Document triage - Legacy migration  - Policy audit      - Web research
```

---

### In-Depth Breakdown of the 5 Task Domains

#### 1. Language Synthesis & Transformation
- **Abstractive & Extractive Summarization:** Compressing 100-page SEC filings, medical records, or transcripts into structured executive briefs while preserving critical semantic nuance.
- **Cross-Lingual Machine Translation:** Translating technical, legal, and colloquial text across dozens of languages, adapting idioms and specialized domain jargon.
- **Style and Tone Adaptation:** Converting technical developer pull request logs into client-facing release notes or adjusting reading grade levels.

#### 2. Information Extraction & Data Structuring
- **Named Entity Recognition (NER) & Relationship Extraction:** Parsing unstructured invoices, clinical trials, or police reports to extract dates, monetary values, organizations, and medical dosages into normalized relational schemas.
- **Unstructured-to-Structured Compilation:** Transforming messy PDF text, OCR scans, or customer support transcripts directly into typed **JSON or XML schemas** conforming to strict Pydantic definitions.
- **Zero-Shot Sentiment & Intent Classification:** Categorizing incoming support tickets by urgency, emotion, and product category without requiring dedicated training data.

#### 3. Code Generation, Analysis & Modernization
- **Natural Language to Executable Code:** Synthesizing complex SQL queries, Python data processing scripts, or React UI components directly from natural language specifications.
- **Automated Bug Localization & Code Review:** Reading execution stack traces, detecting memory leaks, analyzing time complexity ($O(N)$), and generating unit test suites with boundary-value edge cases.
- **Legacy Codebase Modernization:** Translating monolithic legacy code (e.g., COBOL, Fortran, or Python 2) into modern idiomatic Rust, Go, or Python 3.

#### 4. Multi-Step Reasoning & Symbolic Deduction
- **Chain-of-Thought Problem Solving:** Decomposing complex multi-step reasoning problems (e.g., medical differential diagnosis, legal compliance audits, or mathematical proofs) into sequential, verifiable sub-steps.
- **Synthetic Data Generation:** Generating diverse, edge-case-heavy synthetic training datasets to bootstrap smaller downstream ML classifiers or fine-tuning pipelines.

#### 5. Autonomous Tool Use & Agentic Execution
- **Dynamic Tool Calling / Function Calling:** Formulating valid parameters for external deterministic tools—such as querying a Postgres database, querying vector search indices, searching the live web, or invoking external REST APIs—and synthesizing a final grounded response from the returned payloads.

| Task Category | Zero-Shot LLM | LLM + RAG / Tools | Fine-Tuned SLM (8B) | Traditional ML / Deterministic |
| :--- | :--- | :--- | :--- | :--- |
| **Open-Ended Text Drafting** | **Superior** | **Superior** | High | Unusable |
| **Domain-Specific Legal Search** | Poor (Hallucination) | **Superior** | Moderate | Moderate (Keyword only) |

| **Sub-10ms Fraud Detection** | Too Slow ($>200\text{ms}$) | Too Slow | Too Slow | **Optimal (1ms inference)** |

### Tasks LLMs Should NOT Be Assigned to Do Alone

Understanding what an LLM *cannot* do natively is critical for system architects:

```text
                       Tasks Requiring External Tool Scaffolding
                       
Do NOT Use Bare LLM For:                               Proper Production Solution:
1. Exact Complex Arithmetic ($894.23 * 1.0825)  ──────► Python REPL Sandbox / Calculator Tool
2. Real-Time Dynamic Factual Queries           ──────► RAG Pipeline / Web Search API
3. Direct State-Modifying Database Mutations   ──────► Typed ORM / Human-in-the-Loop Confirmation
4. Low-Latency High-Frequency Trading          ──────► C++ / Traditional Statistical Arbitrage
5. Cryptographic Hashing or Random Number Gen  ──────► Hardware Cryptographic Randomness Generator
```

---

### Key Point

> **LLMs act as general-purpose semantic compilers across linguistic synthesis, data extraction, code generation, reasoning, and tool calling; however, deterministic math and live data retrieval must be delegated to external tools.**

---

### Interview Answer

> **LLMs perform a diverse spectrum of tasks across five primary functional domains:
> 1. **Linguistic Synthesis:** Abstractive summarization, machine translation, and tone rewriting.
> 2. **Information Extraction:** Extracting entities and transforming unstructured documents into typed JSON schemas.
> 3. **Software Engineering:** Code synthesis, unit test generation, bug debugging, and legacy code translation.
> 4. **Complex Reasoning:** Multi-step logical deduction, policy compliance analysis, and synthetic data generation.
> 5. **Agentic Tool Calling:** Formulating API requests, querying SQL databases, and synthesizing answers from external tools.
> 
> As an enterprise architect, the key is understanding the boundaries: bare LLMs should never be trusted with exact multi-digit arithmetic or real-time factual lookups without pairing them with external tool execution (like Python sandboxes and RAG pipelines).**
