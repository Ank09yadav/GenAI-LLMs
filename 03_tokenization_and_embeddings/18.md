## 18. What is tokenization?

### Answer

**Tokenization** is the foundational preprocessing pipeline in Natural Language Processing and Large Language Models that transforms an unstructured string of raw characters into a sequence of discrete numerical units called **tokens**, which are subsequently mapped to integer IDs from a fixed, pre-computed vocabulary.

Because neural networks are mathematical tensor operators composed of floating-point matrix multiplications, they cannot consume continuous, variable-length Unicode strings directly. The tokenizer acts as the **bidirectional compiler between continuous human language and discrete tensor indices**.

```text
                               The Complete Tokenization Pipeline
                               
Input String: "Deploying LLMs requires memory planning."
                               │
                               ▼
================ STEP 1: TEXT NORMALIZATION ================
- Unicode NFKC / NFC Normalization
- Lowercasing (if uncased) or case preservation
- Stripping unprintable ASCII control characters
                               │
                               ▼
================ STEP 2: PRE-TOKENIZATION ==================
- Regex-based splitting on whitespace and punctuation boundaries
- GPT-4 / LLaMA regex: partitions words, numbers, and contractions
  Result: ['Deploying', 'ĠLLMs', 'Ġrequires', 'Ġmemory', 'Ġplanning', '.']
                               │
                               ▼
================ STEP 3: SUBWORD SEGMENTATION =============
- Applying learned vocabulary merges (BPE / WordPiece / Unigram)
  Result: ['Deploy', 'ing', 'ĠLL', 'Ms', 'Ġrequires', 'Ġmemory', 'Ġplanning', '.']
                               │
                               ▼
================ STEP 4: VOCABULARY ENCODING ===============
- Lookup in static vocabulary dictionary V (Size: 32,000 to 128,256)
Token IDs: [34812, 278, 18920, 4129, 3918, 2940, 6814, 13]
```

---

### The Two Directions of a Tokenizer

A production tokenizer is strictly a **losslessly reversible mathematical mapping**:

#### 1. Encoding (String $\to$ Token IDs)
$$\text{Tokens} = \operatorname{Encode}(\text{Text}) \in \mathbb{Z}^N$$
Converts raw strings into an ordered 1D tensor of integer IDs that can be passed to the model's embedding matrix lookup layer:
$$\mathbf{X}_0 = \operatorname{EmbeddingLookup}(\text{Token IDs}) \in \mathbb{R}^{N \times d_{\text{model}}}$$

#### 2. Decoding (Token IDs $\to$ String)
$$\text{Text} = \operatorname{Decode}(\text{Tokens})$$
Reconstitutes generated integer tokens into human-readable characters, merging subwords, decoding UTF-8 byte streams, and reconstructing whitespace markers (`Ġ` in GPT or ` ` in SentencePiece).

### Why Tokenizer Choice is a Core Engineering Decision

The configuration of a tokenizer dictates critical operational characteristics:

```text
                               Impact of Tokenizer Design
                                           │
     ┌───────────────────┬─────────────────┼─────────────────┬───────────────────┐
     ▼                   ▼                 ▼                 ▼                   ▼
[Vocabulary Size (|V|)] [Compression Ratio][Multilingual Cost] [Code Formatting]   [Arithmetic]
32k vs 128k parameters   Chars per token   Tokens per non-   Indentation &       Digit segmentation
affect VRAM footprint    governs throughput Latin word       spaces as tokens    (123 vs 1 + 2 + 3)
```

1. **Vocabulary Size ($|V|$):** 
   - LLaMA-1/2 used a vocabulary of $32,000$ tokens.
   - LLaMA-3 and GPT-4o expanded the vocabulary to $128,256$ tokens.
   - *Tradeoff:* A larger vocabulary achieves higher compression (fewer tokens per document), but increases the parameter memory of the input embedding matrix and the final linear unembedding head ($|V| \times d_{\text{model}}$).
2. **Compression Ratio:** How many characters of natural language are represented per token. Higher compression means more semantic content fits within a fixed context window (e.g., 8k tokens).
3. **Multilingual Fertility:** A tokenizer trained predominantly on English will fragment non-Latin scripts (Hindi, Japanese, Arabic) into multiple individual bytes, causing inference latency and API costs to spike by **$3\times - 6\times$** for international users!

### Key Point

> **Tokenization is the discrete translation boundary between human text and the neural network, segmenting strings into subword vocabulary pieces and mapping them to integer IDs.**

### Interview Answer

> **Tokenization is the discrete compiler interface between human text and a deep neural network. Because Transformers operate on continuous mathematical tensors rather than arbitrary character strings, the tokenizer converts text into a sequence of discrete integer identifiers from a fixed vocabulary.
> 
> The pipeline executes across four standardized stages:
> 1. **Text Normalization:** Standardizing Unicode (NFKC) and whitespace.
> 2. **Pre-tokenization:** Splitting text into coarse word and symbol chunks using regex.
> 3. **Subword Segmentation:** Applying learned algorithms like Byte-Pair Encoding (BPE) or WordPiece to segment rare words into shared morphological subwords.
> 4. **Vocabulary Mapping:** Translating subword strings into integer token IDs.
> 
> The efficiency of a tokenizer directly governs an application\'s operational economics: it determines sequence length (and therefore quadratic self-attention memory), multilingual cost parity, and how effectively the model processes numbers and code indentation.**
