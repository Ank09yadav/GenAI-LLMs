## 23. What are embeddings?

### Answer

An **Embedding** is a mathematical mapping that projects discrete categorical entities (such as words, subword tokens, sentences, entire documents, or images) into a **continuous, dense, low-dimensional vector space** ($\mathbb{R}^d$), where geometric proximity, distance, and orientation mirror semantic, syntactic, and conceptual relationships.

Before modern embeddings, natural language processing relied on **One-Hot Encodings**, where every word in a vocabulary of size $|V|$ was represented as a massive sparse vector with a single `1` and $|V| - 1$ zeros:

```text
The Failure of One-Hot Encodings:
Vocabulary: ["cat", "dog", "automobile", "car"]  (Dimension: |V| = 4)
"cat":        [1, 0, 0, 0]
"dog":        [0, 1, 0, 0]
"automobile": [0, 0, 1, 0]
"car":        [0, 0, 0, 1]

The Mathematical Breakdown:
DotProduct("cat", "dog")        = 0.0 (Orthogonal - zero similarity!)
DotProduct("car", "automobile") = 0.0 (Orthogonal - zero similarity!)
*Result: The computer has zero geometric understanding that a cat is closer to a dog 
than to a car, or that "car" and "automobile" are identical synonyms!*
```

In contrast, **Dense Vector Embeddings** place semantically related concepts into continuous geometric clusters:

```text
Dense Vector Embeddings (Dimension d = 3 for visualization):
"cat":        [ 0.82, -0.41,  0.77 ]
"dog":        [ 0.79, -0.38,  0.81 ]  ──► Cosine Similarity = +0.98 (High Similarity!)
"automobile": [-0.12,  0.88, -0.45 ]
"car":        [-0.14,  0.85, -0.48 ]  ──► Cosine Similarity = +0.99 (Synonyms!)
"car" vs "cat"                       ──► Cosine Similarity = +0.12 (Orthogonal / Unrelated)
```

### Geometric Properties of Embedding Spaces

```text
                          Dense Embedding Vector Space
                                      ▲
                         Queen ●      │      ● King
                                      │
                                      │  Vector offset: "gender direction"
                         Woman ●      │      ● Man
                                      │
                         ─────────────┼──────────────────────────►
                                      │
                                      │       ● Automobile
                                      │  ● Car
```

#### 1. Linear Vector Arithmetic (Semantic Analogies)
Dense embeddings capture relational analogies through linear vector addition and subtraction:
$$\vec{v}_{\text{King}} - \vec{v}_{\text{Man}} + \vec{v}_{\text{Woman}} \approx \vec{v}_{\text{Queen}}$$
$$\vec{v}_{\text{Paris}} - \vec{v}_{\text{France}} + \vec{v}_{\text{Japan}} \approx \vec{v}_{\text{Tokyo}}$$

#### 2. Metric Space Distance Formulations
Semantic similarity in embedding spaces is calculated using three primary mathematical distance functions:

- **Cosine Similarity (Orientation Matching):** Measures the cosine of the angle between two vectors, invariant to vector magnitude:
  $$\operatorname{CosineSim}(\mathbf{u}, \mathbf{v}) = \frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\|_2 \|\mathbf{v}\|_2} = \frac{\sum_{i=1}^d u_i v_i}{\sqrt{\sum_{i=1}^d u_i^2} \sqrt{\sum_{i=1}^d v_i^2}}$$
- **Euclidean Distance ($L_2$ Norm):** Measures straight-line distance in Euclidean space:
  $$d_{L_2}(\mathbf{u}, \mathbf{v}) = \sqrt{\sum_{i=1}^d (u_i - v_i)^2}$$
- **Inner Product (Dot Product):** If embedding vectors are normalized to unit length ($\|\mathbf{u}\|_2 = 1$), the dot product is **mathematically identical to cosine similarity**:
  $$\mathbf{u} \cdot \mathbf{v} = \operatorname{CosineSim}(\mathbf{u}, \mathbf{v})$$
  *(This property enables modern vector databases to run ultra-fast dot-product hardware instructions!)*

### The Four Major Categories of Embeddings

```text
                           Taxonomy of Modern Embeddings
                                         │
     ┌──────────────────────┬────────────┴────────────┬──────────────────────┐
     ▼                      ▼                         ▼                      ▼
[Token Embeddings]     [Sentence Embeddings]     [Code Embeddings]     [Multimodal (CLIP)]
Input weights inside   Bi-encoder models for     Embeds AST & syntax   Aligns image & text
LLMs (d = 4096)        Vector DBs (d = 1536)     for code search       vectors in same space
```

1. **Token Embeddings:** The initial lookup table ($\mathbf{W}_{\text{embed}} \in \mathbb{R}^{|V| \times d_{\text{model}}}$) inside a Transformer that projects individual token IDs into hidden dimension vectors.
2. **Sentence / Document Embeddings:** Standalone models (e.g., BGE, E5, OpenAI `text-embedding-3-small`) trained via contrastive loss to pool an entire document into a single vector for **vector database retrieval in RAG**.
3. **Multimodal Embeddings (CLIP):** Models that project both images and natural language text into the **exact same joint geometric space**, allowing an image of a dog to match the text string `"golden retriever"` via cosine similarity.

### Comparison: One-Hot vs. Sparse TF-IDF vs. Dense Embeddings

| Feature | One-Hot Encoding | Sparse TF-IDF / BM25 | Dense Embeddings (Modern) |
| :--- | :--- | :--- | :--- |
| **Vector Dimensionality** | $|V|$ (Tens of thousands) | $|V|$ (Tens of thousands) | **$768$ to $4,096$ (Compact)** |
| **Vector Density** | $99.99\%$ Zeros (Extremely sparse) | $99.5\%$ Zeros (Sparse) | **$100\%$ Non-Zero (Dense continuous)** |
| **Semantic Awareness**| None (All words orthogonal) | Lexical frequency only | **High (Captures synonyms & concepts)**|
| **Synonym Matching** | Impossible | Fails ("car" != "automobile") | **Native & Automatic** |
| **Storage in Database**| Inefficient | Inverted Index | **Vector Index (HNSW / IVF)** |

### Key Point

> **Embeddings project discrete categorical entities into a continuous geometric vector space, converting semantic relationships into measurable spatial angles and distances.**

---

### Interview Answer

> **An embedding is a continuous, dense vector representation of discrete entities such as words, subword tokens, sentences, or images in a learned geometric space (typically 768 to 4096 dimensions). 
> 
> Unlike traditional one-hot encodings where all vectors are mutually orthogonal and have zero semantic awareness, dense embeddings capture conceptual and syntactic relationships: semantically related concepts are placed close together in vector space, allowing mathematical operations like cosine similarity or Euclidean distance to measure semantic similarity.
> 
> In modern production systems, embeddings exist in two distinct formats:
> 1. **Internal Token Embeddings:** The input projection matrix inside an LLM that translates token IDs into hidden layer representations.
> 2. **Sentence/Document Embeddings:** Produced by contrastively trained bi-encoders (like BGE or OpenAI embeddings) to index and retrieve documents in vector databases for RAG pipelines.**
