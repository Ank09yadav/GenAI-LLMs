## 26. How is an LLM trained?

### Answer

Training a modern Large Language Model (LLM) is one of the most computationally demanding and technically sophisticated engineering workflows in computer science. Modern state-of-the-art LLMs (such as LLaMA-3, GPT-4, and Claude) are not created in a single training run; instead, they are forged through an end-to-end **three-phase lifecycle**:

```text
                                  The Complete LLM Training Lifecycle
                                  
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │ STAGE 1: Self-Supervised Pretraining                                                        │
 │ ─────────────────────────────────────────────────────────────────────────────────────────── │
 │ Data: Trillions of raw tokens (Web crawl, Common Crawl, Wikipedia, GitHub, ArXiv, Books)   │
 │ Objective: Causal Next-Token Prediction: min L_pretrain = - Σ log P(x_t | x_<t; θ)         │
 │ Compute Share: ~98% - 99% of total floating-point operations (FLOPs)                        │
 │ Output: "Base Model" (e.g., LLaMA-3-8B-Base) — Raw text predictor, lacks conversational tact│
 └──────────────────────────────────────────────┬──────────────────────────────────────────────┘
                                                │
                                                ▼
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │ STAGE 2: Supervised Fine-Tuning (SFT) / Instruction Tuning                                  │
 │ ─────────────────────────────────────────────────────────────────────────────────────────── │
 │ Data: Curated (Prompt, Demonstration Response) pairs (10K - 1M high-quality examples)       │
 │ Objective: Masked Causal Cross-Entropy over completion tokens only (Prompt tokens masked)   │
 │ Compute Share: ~1% of total training FLOPs                                                  │
 │ Output: "Instruct Model" (e.g., LLaMA-3-8B-SFT) — Follows directions, answers queries       │
 └──────────────────────────────────────────────┬──────────────────────────────────────────────┘
                                                │
                                                ▼
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │ STAGE 3: Preference Alignment (RLHF or DPO)                                                 │
 │ ─────────────────────────────────────────────────────────────────────────────────────────── │
 │ Data: Paired comparisons (Prompt x, Preferred y_w, Rejected y_l)                            │
 │ Objective: Maximize human preference reward while penalizing drift via KL Divergence        │
 │ Methods: PPO with Reward Model or Direct Preference Optimization (DPO)                      │
 │ Compute Share: < 1% of total training FLOPs                                                 │
 │ Output: "Aligned Production Model" (e.g., LLaMA-3-8B-Instruct, ChatGPT) — Helpful & Safe    │
 └─────────────────────────────────────────────────────────────────────────────────────────────┘
```

---

### Detailed Breakdown of the Three Stages

#### 1. Self-Supervised Pretraining (The Knowledge Engine)
- **Goal:** Impart grammar, syntax, general reasoning, mathematical intuition, coding logic, and broad world knowledge into the model's weights.
- **Data Scale:** 3 to 15+ trillion tokens. Filtered rigorously through deduplication (MinHash/SimHash), heuristic safety rules, quality classifiers, and language identification.
- **Mathematical Loss:** Standard autoregressive cross-entropy across all tokens in the context window:
  $$\mathcal{L}_{\text{pretrain}}(\theta) = -\frac{1}{T} \sum_{t=1}^{T} \log P(x_t \mid x_1, x_2, \dots, x_{t-1}; \theta)$$
- **Hardware & Scale:** Thousands of GPUs (e.g., 16,384 NVIDIA H100s) operating synchronously across weeks or months using 3D parallelism (Tensor Parallelism, Pipeline Parallelism, and Data Parallelism with ZeRO-3 / FSDP).

#### 2. Supervised Fine-Tuning (SFT / Instruction Tuning)
- **Goal:** Transform a raw "autocomplete engine" into an interactive, conversational assistant. A base model asked *"What is the capital of France?"* might complete the text with *"What is the capital of Germany? What is the capital of Italy?"* because it treats the input as an exam paper. SFT teaches the model to answer directly: *"The capital of France is Paris."*
- **Data Scale:** 10,000 to 1,000,000 high-quality instruction-response dialogues.
- **Masked Token Loss:** SFT computes loss **only** on the assistant's tokens, masking out prompt tokens so the model is not penalized for learning the distribution of user queries:
  $$\mathcal{L}_{\text{SFT}}(\theta) = -\sum_{t \in \text{Completion}} \log P(y_t \mid x_{\text{prompt}}, y_{<t}; \theta)$$

#### 3. Preference Alignment (RLHF / DPO)
- **Goal:** Align model behavior with the **HHH Criteria** (Helpful, Honest, Harmless).
- **Techniques:**
  - **Reinforcement Learning from Human Feedback (RLHF):** Trains a separate Reward Model $R_\psi(x, y)$ on human preference pairs, then optimizes the policy model using Proximal Policy Optimization (PPO) with a KL-divergence penalty to prevent policy collapse.
  - **Direct Preference Optimization (DPO):** Mathematically solves for the optimal policy directly from preference data, bypassing the need for an explicit reward model.

### Lifecycle Comparison Matrix

| Stage | Input Data | Volume | Optimization Objective | Hardware Cost | Typical Failure Mode |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Pretraining** | Unstructured web text, books, code | $10^{12} - 10^{13}$ tokens | Causal Next-Token Cross-Entropy | Millions of USD (98-99% of total) | Hardware loss spikes, dead neurons, GPU silent data corruption |
| **SFT** | Instruction-response pairs | $10^4 - 10^6$ examples | Masked completion cross-entropy | Thousands of USD (~1% of total) | Style overfitting, hallucination amplification, loss of diversity |
| **Alignment** | Paired preferences $(x, y_w, y_l)$ | $10^4 - 10^5$ pairs | PPO / DPO objective with KL penalty | Hundreds of USD (< 1% of total) | Sycophancy, excessive refusal (over-safety), mode collapse |

---

### Key Training Dynamics and Engineering Infrastructure

1. **Learning Rate Schedules:** Pretraining typically employs a linear warmup for the first 2,000–5,000 steps, followed by a **Cosine Decay** schedule down to 10% of the peak learning rate. A final "annealing" phase with ultra-high-quality data is often used to sharpen model performance.
2. **Numerical Precision:** Modern LLMs are trained in **BF16** (Bfloat16) or mixed **FP8** to conserve GPU VRAM and maximize tensor core throughput while preventing the underflow/overflow issues historically encountered with FP16.
3. **Loss Spikes:** Massive training runs frequently experience sudden, catastrophic loss spikes. Engineering teams combat these via gradient clipping (typically at $\|\mathbf{g}\|_2 \le 1.0$), checkpoint rollback, skip-batch mechanisms, and data-order reshuffling.

---

### Key Point

> **LLM training is a sequential three-stage pipeline: Pretraining ingests trillions of unlabelled tokens to build foundational world representations (98%+ of compute); Supervised Fine-Tuning (SFT) shapes conversational behavior; and Preference Alignment (RLHF/DPO) steers the model toward safe, helpful human preferences.**

---

### Interview Answer

> "An LLM is trained through three distinct stages:
> 1. **Pretraining:** The model learns grammar, facts, and reasoning by predicting the next token across trillions of tokens of text and code using self-supervised causal language modeling. This accounts for over 98% of the compute budget and yields the 'Base' model.
> 2. **Supervised Fine-Tuning (SFT):** The base model is adapted into a conversational assistant using tens of thousands of high-quality instruction-response pairs, training exclusively on completion tokens.
> 3. **Preference Alignment (RLHF or DPO):** The model is fine-tuned against human preference data (chosen vs. rejected responses) to enforce safety, eliminate toxicity, curb hallucinations, and maximize helpfulness."
