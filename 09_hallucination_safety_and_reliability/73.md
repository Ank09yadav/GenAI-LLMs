## 73. How would you build guardrails around an LLM application?

### Answer

Building enterprise-grade guardrails around an LLM application requires an **in-depth defense perimeter** that wraps the probabilistic model in deterministic and specialized classification layers at both the **input stage (before invocation)** and the **output stage (before client delivery)**.

A common enterprise failure is attempting to enforce all safety and formatting rules inside the system prompt. System prompts are easily bypassed or diluted. Production guardrails decouple safety enforcement from the core model into **dedicated, fast, deterministic software components**.

```text
                     Production Guardrails Architecture
                     
[Client User Request]
        │
        ▼
================ INPUT GUARDRAIL LAYER (<30ms) ================
├─► 1. Token-Bucket Rate Limiter & Length Verifier
├─► 2. PII / Secret Detection & Vaulting (Microsoft Presidio)
├─► 3. Semantic Topical Boundary Check (Cosine Similarity Gate)
└─► 4. Adversarial Prompt Injection / Jailbreak Classifier (Llama Guard 3)
        │
        ▼ (Passed Input Validation)
================ CORE ORCHESTRATION & INFERENCE ================
├─► Assembled System Instructions & Context Delimiters
├─► Deterministic Generation Parameters (T = 0.0)
└─► Grammar-Constrained Logit Masking (Pydantic / Outlines)
        │
        ▼ (Raw Generation Generated)
================ OUTPUT GUARDRAIL LAYER (<40ms) ================
├─► 1. Structural Schema Validation (Strict JSON / Pydantic Parser)
├─► 2. Grounding & Faithfulness Verification (NLI Entailment Check)
├─► 3. Toxicity, Hate & Safety Compliance Scanner
└─► 4. Secret / System Prompt Leakage Regex Filter
        │
        ▼ (Passed Output Validation)
[Sanitized, Audited Response Delivered to Client]
```

### The Three Guardrail Operational Tiers

#### 1. Input Guardrails (Pre-Execution Filtration)
- **PII & Credential Redaction:** Intercept credit card numbers, Social Security numbers, email addresses, and API keys using regex and named-entity recognition (NER via Microsoft Presidio). Replace sensitive values with ephemeral tokens before they leave the VPC.
- **Topical Cannons (Semantic Bounds):** In domain-specific applications (e.g., a banking customer portal), verify that the incoming prompt pertains to allowed topics. Compute cosine similarity between the query embedding and pre-computed cluster centroids of valid enterprise domains. If a user asks the banking bot to *write a poem about space*, reject it in 10ms with zero LLM API cost!
- **Prompt Injection & Jailbreak Scanners:** Pass the prompt through a lightweight, specialized safety classifier (such as **Llama Guard 3** or a fine-tuned DeBERTa model) to catch injection payloads before they touch the primary LLM.

#### 2. Execution-Time Guardrails (Runtime Constraints)
- **Grammar-Constrained Decoding:** Never rely on the model to "please format as JSON". Use engines like Outlines or vLLM guided decoding that build a Finite State Machine from a Pydantic schema and mask invalid tokens at the logit level during every forward pass.
- **Strict Context Delimitation:** Encapsulate untrusted user context in distinct XML containers (`<untrusted_data>`) with system instructions commanding the model to treat the contents strictly as passive text.

#### 3. Output Guardrails (Post-Execution Validation)
- **Structural Integrity Gate:** Parse the completed string against the target schema. If parsing fails, trigger an automated retry loop with error feedback, or return a safe default fallback.
- **Grounding & Factuality Verifier:** For RAG pipelines, pass the generated claims through a Natural Language Inference (NLI) model to calculate a Groundedness score against retrieved documents. If the score falls below a threshold (e.g., 0.90), quarantine the response.
- **System Prompt Leakage Detection:** Run fuzzy string matching between the generated text and the confidential system prompt. If the model inadvertently quoted internal developer directives, suppress the response.

### Concrete Production Implementation: FastAPI Multi-Stage Guardrail Middleware

Below is a complete, runnable production FastAPI pipeline illustrating multi-stage input and output guardrails:

```python
import re
from fastapi import FastAPI, HTTPException, Request
from pydantic import BaseModel, Field
from typing import Dict, Any

app = FastAPI(title="Guarded LLM Gateway")

class UserQuery(BaseModel):
    query: str = Field(..., max_length=1000)

class SafeResponse(BaseModel):
    response: str
    status: str
    grounded: bool

# 1. Deterministic Input Guardrail: PII and Injection Pattern Detector
def input_guardrail(text: str) -> str:
    # Check for prompt injection signatures
    injection_patterns = [
        r"(?i)ignore\s+(previous|all)\s+instructions",
        r"(?i)system\s+override",
        r"(?i)you\s+are\s+now\s+in\s+dan\s+mode",
    ]
    for pattern in injection_patterns:
        if re.search(pattern, text):
            raise HTTPException(status_code=400, detail="Security violation: Adversarial prompt detected.")

    # Redact Social Security Numbers (Simple demonstration regex)
    sanitized = re.sub(r"\b\d{3}-\d{2}-\d{4}\b", "[REDACTED_SSN]", text)
    return sanitized

# 2. Deterministic Output Guardrail: Leakage & Secret Filter
def output_guardrail(raw_output: str, confidential_system_key: str) -> str:
    # Check for internal system prompt leakage
    if confidential_system_key in raw_output:
        return "I apologize, but I am unable to display the requested response due to internal policy constraints."
    return raw_output

@app.post("/v1/chat/guarded", response_model=SafeResponse)
async def guarded_chat(payload: UserQuery):
    # Pass through Input Guardrails
    clean_prompt = input_guardrail(payload.query)

    # Simulated Core LLM Call
    confidential_key = "INTERNAL_SECRET_PROJECT_CODENAME"
    # (In real system: call vLLM / OpenAI with clean_prompt)
    simulated_raw_llm_output = f"Processed inquiry for: {clean_prompt}."

    # Pass through Output Guardrails
    verified_output = output_guardrail(simulated_raw_llm_output, confidential_key)

    return SafeResponse(
        response=verified_output,
        status="SUCCESS",
        grounded=True
    )
```

### Key Point

> **Production guardrails enforce multi-stage defense-in-depth: combining deterministic regex and PII masking, embedding-based topical gates, Llama Guard injection classifiers, and post-generation NLI factuality verifiers.**

### Interview Answer

> **I architect production guardrails as an external, multi-layered security and validation perimeter decoupled from the core LLM:
> 
> 1. **Input Guardrails (Pre-Inference):** Incoming requests first pass through deterministic PII redaction (using Microsoft Presidio) to mask sensitive data into encrypted tokens. We then run an embedding-based topical classifier to reject off-domain queries early, followed by a dedicated safety model (like Llama Guard 3) to intercept prompt injection and jailbreaks.
> 2. **Execution-Time Guardrails:** We employ grammar-constrained decoding (via Outlines or vLLM guided decoding) to force mathematical compliance to JSON/Pydantic schemas at the logit level, eliminating syntax hallucinations.
> 3. **Output Guardrails (Post-Inference):** The generated completion is parsed by Pydantic, checked against confidential system prompt leakage filters, and evaluated for factual groundedness using a lightweight NLI cross-encoder.
> 
> By running fast, deterministic checks at the gateway, we keep total guardrail latency under 40 milliseconds while guaranteeing compliance and data integrity.**
