## 11. What are Query, Key, and Value?

### Answer

The concept of **Query ($Q$)**, **Key ($K$)**, and **Value ($V$)** is borrowed from information retrieval systems and dictionary lookup data structures (such as hash maps or SQL databases):

```text
Information Retrieval Analogy:
- Query: What you type into the search bar (The target or question you are asking).
- Key:   The metadata tags, titles, or indexing labels of documents in the database.
- Value: The actual content, text, or payload contained within the matched document.

Traditional Hard Lookup (Hash Map):
hash_map.get(Query) ──► Exact Match against Key ──► Return 100% of the single Value

Transformer Soft Differentiable Lookup (Self-Attention):
Query dot-product with ALL Keys ──► Normalized Softmax Probabilities ──► Weighted Sum of ALL Values
```

In a Transformer, attention is a **soft, differentiable, continuous lookup**: instead of retrieving a single discrete value, the model computes a continuous similarity score against every key in the sequence and aggregates a weighted blend of all value vectors.

---

### Mathematical Vector Formulations

Given an input matrix of token representations $\mathbf{X} \in \mathbb{R}^{N \times d_{\text{model}}}$, three distinct learned projection matrices project the tokens into specialized representation subspaces:

$$\mathbf{Q} = \mathbf{X} \mathbf{W}_Q \quad \text{where } \mathbf{W}_Q \in \mathbb{R}^{d_{\text{model}} \times d_k} \quad \text{("What am I looking for in my context?")}$$
$$\mathbf{K} = \mathbf{X} \mathbf{W}_K \quad \text{where } \mathbf{W}_K \in \mathbb{R}^{d_{\text{model}} \times d_k} \quad \text{("What content or role do I advertise?")}$$
$$\mathbf{V} = \mathbf{X} \mathbf{W}_V \quad \text{where } \mathbf{W}_V \in \mathbb{R}^{d_{\text{model}} \times d_v} \quad \text{("What actual semantic information do I convey if matched?")}$$

```text
Tensor Dimensional Shapes:
Sequence Matrix X:          [Batch Size, Sequence Length N, Hidden Dim d_model]
Projection Weights W_Q,K,V: [Hidden Dim d_model, Head Dim d_k]
Resulting Tensors Q, K:     [Batch Size, Sequence Length N, Head Dim d_k]
Resulting Tensor V:         [Batch Size, Sequence Length N, Head Dim d_v]
```

---

### Step-by-Step Soft Attention Computation

```text
                 Step-by-Step Interaction of Q, K, and V
                 
Token i Query (q_i)          Token j Key (k_j)
         │                          │
         └──────────► MatMul ◄──────┘
                         │
                         ▼
             Raw Score: s_ij = q_i · k_j^T
                         │
                         ▼
             Scale by 1 / sqrt(d_k)
                         │
                         ▼
             Softmax Normalization across all j:
             α_ij = exp(s_ij / sqrt(d_k)) / Sum(exp(s_im / sqrt(d_k)))
                         │  (Attention Weights α_ij summing to 1.0)
                         ▼
                      MatMul ◄───── Token j Value (v_j)
                         │
                         ▼
       Enriched Output Vector for Token i = Sum(α_ij * v_j)
```

1. **Alignment Score ($s_{ij}$):** Compute the dot product between the Query of token $i$ and the Key of token $j$:
   $$s_{ij} = \mathbf{q}_i \cdot \mathbf{k}_j^T$$
   High positive dot product indicates high semantic relevance.
2. **Scaling Factor ($\sqrt{d_k}$):** Divide by $\sqrt{d_k}$ to prevent gradient vanishing during softmax.
3. **Softmax Weights ($\alpha_{ij}$):** Normalize scores across all tokens $j \in \{1, \dots, N\}$ to create a valid probability distribution:
   $$\alpha_{ij} = \frac{\exp\left(\frac{\mathbf{q}_i \mathbf{k}_j^T}{\sqrt{d_k}}\right)}{\sum_{m=1}^N \exp\left(\frac{\mathbf{q}_i \mathbf{k}_m^T}{\sqrt{d_k}}\right)}$$
4. **Value Aggregation:** Multiply the attention weights by the Value vectors to form the contextualized output:
   $$\mathbf{y}_i = \sum_{j=1}^N \alpha_{ij} \mathbf{v}_j$$

### Concrete Linguistic Walkthrough: Coreference Resolution

Consider the famous Winograd Schema sentence:
> *"The animal didn't cross the street because **it** was too tired."*

How does the model resolve what **"it"** refers to?

```text
Token of Interest: "it" (Position 8)

1. Query Vector of "it":
   Query("it"): "I am a pronoun looking for a singular noun that possesses states of fatigue or physical capability."

2. Key Vector of "animal":
   Key("animal"): "I am a biological organism capable of fatigue and physical movement."
   ──► Alignment: Query("it") · Key("animal") = +14.2 (High Score!)

3. Key Vector of "street":
   Key("street"): "I am an inanimate asphalt roadway; I cannot experience fatigue."
   ──► Alignment: Query("it") · Key("street") = +1.1 (Low Score!)

4. Softmax Weights:
   α("it" -> "animal") = 0.89
   α("it" -> "street") = 0.04

5. Value Output:
   The representation of "it" absorbs 89% of Value("animal")! 
   The model's internal representation of "it" is now mathematically synonymous with the animal!
```

If the sentence instead read: *"The animal didn't cross the street because **it** was too wide"*, the Query of *"it"* would search for an entity with physical dimensions, matching Key(*"street"*), pulling Value(*"street"*).

### Why Not Just Compute Attention on Raw Input Embeddings ($\mathbf{X} \mathbf{X}^T \mathbf{X}$)?

A common interview question asks: *"Why do we need three separate projection matrices $\mathbf{W}_Q, \mathbf{W}_K, \mathbf{W}_V$? Why not calculate $\operatorname{softmax}(\mathbf{X} \mathbf{X}^T) \mathbf{X}$?"*

1. **Role Asymmetry:** A word's role as a *seeker* of information is fundamentally different from its role as a *provider* of information. If $\mathbf{Q} = \mathbf{K}$, the dot product $\mathbf{x}_i \cdot \mathbf{x}_j$ would be strictly symmetric ($s_{ij} = s_{ji}$). In natural language, relationship directions are asymmetric: a verb acts upon an object, but an object does not act upon the verb.
2. **Subspace Specialization:** Linear projections map tokens into specialized semantic subspaces where syntactic, grammatical, and relational features can be isolated from raw lexical meaning.
3. **Decoupling Scoring from Content:** Keys determine *who* gets selected; Values determine *what* information is actually transmitted once selected.

---

### Key Point

> **Queries represent the information tokens seek, Keys represent the index tags tokens advertise, and Values represent the actual content transmitted when a match occurs.**

---

### Interview Answer

> **Query, Key, and Value are vector projections inspired by retrieval systems. In self-attention, they allow tokens to dynamically look up and route information across a sequence:
> 
> - **Query ($Q = X W_Q$):** Represents what a token is seeking or asking about its surrounding context.
> - **Key ($K = X W_K$):** Represents what a token offers or advertises to other tokens.
> - **Value ($V = X W_V$):** Contains the actual semantic payload transferred when a match occurs.
> 
> We compute the dot product between a token\'s Query and all other tokens\' Keys to measure semantic alignment. These raw scores are scaled by $\frac{1}{\sqrt{d_k}}$ and normalized via softmax to produce attention weights summing to 1.0. These weights then compute a linear weighted sum over the Value vectors, producing an enriched, context-aware token representation.
> 
> Having distinct projection matrices is critical because it decouples the addressing mechanism (Queries and Keys) from the content payload (Values) and allows the network to model directional, asymmetric relationships between tokens.**
