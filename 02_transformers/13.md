## 13. What is multi-head attention?

### Answer

**Multi-Head Attention (MHA)** is an architectural mechanism that runs the scaled dot-product attention calculation multiple times in parallel across different learned projection subspaces, rather than computing attention once in a single monolithic hidden dimension.

Vaswani et al. discovered that a single attention head tends to **average multiple competing linguistic relationships** into a single homogeneous vector. By projecting queries, keys, and values into $h$ distinct lower-dimensional "heads", each head can independently specialize in different syntactic, grammatical, semantic, or positional patterns.

```text
Single-Head Attention (Averaged Subspace Bottleneck):
Q, K, V (dim 4096) ──► Attention ──► One averaged blend of all semantic relations

Multi-Head Attention (h = 8 heads, d_k = 512 each):
         ┌──► Head 1: Syntactic Dependencies (Subject-Verb agreement) ────┐
         ├──► Head 2: Coreference Resolution (Linking "it" to "the dog")  ├──┐
Q, K, V ─┼──► Head 3: Long-Range Temporal Sequences (Dates, chronology)   ──┼──► Concat ──► W_O ──► Output
         └──► Head 8: Local Positional Proximity (Adjacent word context)  ──┘
```

---

### Mathematical Formulation of Multi-Head Attention

Given input representations $\mathbf{Q}, \mathbf{K}, \mathbf{V} \in \mathbb{R}^{N \times d_{\text{model}}}$, we define $h$ parallel attention heads. For each head $i \in \{1, \dots, h\}$:

$$\operatorname{head}_i = \operatorname{Attention}\left(\mathbf{Q} \mathbf{W}_i^Q, \, \mathbf{K} \mathbf{W}_i^K, \, \mathbf{V} \mathbf{W}_i^V\right)$$

where the learned projection parameter matrices are:
$$\mathbf{W}_i^Q \in \mathbb{R}^{d_{\text{model}} \times d_k}, \quad \mathbf{W}_i^K \in \mathbb{R}^{d_{\text{model}} \times d_k}, \quad \mathbf{W}_i^V \in \mathbb{R}^{d_{\text{model}} \times d_v}$$

The outputs of all $h$ heads are concatenated along the feature dimension and projected back to $d_{\text{model}}$ using an output projection matrix $\mathbf{W}^O$:

$$\operatorname{MultiHead}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \operatorname{Concat}\left(\operatorname{head}_1, \operatorname{head}_2, \dots, \operatorname{head}_h\right) \mathbf{W}^O$$

where $\mathbf{W}^O \in \mathbb{R}^{(h \cdot d_v) \times d_{\text{model}}}$.

#### The Computational Invariant
In standard design:
$$d_k = d_v = \frac{d_{\text{model}}}{h}$$
- For example, if $d_{\text{model}} = 4096$ and $h = 32$ heads, then $d_k = 4096 / 32 = 128$.
- Because each head operates on a reduced dimension ($128$), **the total computational cost and parameter count of multi-head attention is identical to single-head attention on the full dimension!**

### The Evolution: MHA vs. MQA vs. GQA

As context lengths expanded from 2,048 tokens to 128,000+ tokens, storing the Key and Value tensors for all heads in the **KV cache during inference** became the single greatest memory bottleneck in LLM serving. 

This forced the industry to evolve from MHA to **MQA** and **GQA**:

```text
1. Multi-Head Attention (MHA - Original Transformer):
   Query Heads: 8   Key Heads: 8   Value Heads: 8
   ┌────┬────┬────┬────┬────┬────┬────┬────┐  (Queries)
   │ Q1 │ Q2 │ Q3 │ Q4 │ Q5 │ Q6 │ Q7 │ Q8 │
   ├────┼────┼────┼────┼────┼────┼────┼────┤
   │ K1 │ K2 │ K3 │ K4 │ K5 │ K6 │ K7 │ K8 │  (Keys: Separate head for every Query)
   ├────┼────┼────┼────┼────┼────┼────┼────┤
   │ V1 │ V2 │ V3 │ V4 │ V5 │ V6 │ V7 │ V8 │  (Values: Separate head for every Query)
   └────┴────┴────┴────┴────┴────┴────┴────┘
   *Problem: KV cache memory footprint is massive during inference.*

2. Multi-Query Attention (MQA - Noam Shazeer, 2019):
   Query Heads: 8   Key Heads: 1   Value Heads: 1
   ┌────┬────┬────┬────┬────┬────┬────┬────┐  (Queries)
   │ Q1 │ Q2 │ Q3 │ Q4 │ Q5 │ Q6 │ Q7 │ Q8 │
   ├────┴────┴────┴────┴────┴────┴────┴────┤
   │                   K1                  │  (Keys: All Queries share ONE Key head!)
   ├───────────────────────────────────────┤
   │                   V1                  │  (Values: All Queries share ONE Value head!)
   └───────────────────────────────────────┘
   *Benefit: Slashes KV cache memory by 8x. Drawback: Slight degradation in model quality.*

3. Grouped-Query Attention (GQA - Ainslie et al., 2023 - Modern Standard):
   Query Heads: 8   Key Heads: 2   Value Heads: 2 (Groups of 4 Queries per KV head)
   ┌────┬────┬────┬────┐  ┌────┬────┬────┬────┐  (Queries)
   │ Q1 │ Q2 │ Q3 │ Q4 │  │ Q5 │ Q6 │ Q7 │ Q8 │
   ├────┴────┴────┴────┤  ├────┴────┴────┴────┤
   │        K1         │  │        K2         │  (Keys: Shared across groups of 4)
   ├───────────────────┤  ├───────────────────┤
   │        V1         │  │        V2         │  (Values: Shared across groups of 4)
   └───────────────────┘  └───────────────────┘
   *Benefit: Optimal sweet spot! 4x to 8x KV cache reduction with near-zero quality degradation.*
   *Used in: LLaMA-2/3, Mistral-7B, Qwen-2.5, DeepSeek.*
```

### Technical Comparison: MHA vs. MQA vs. GQA

| Feature | Multi-Head Attention (MHA) | Multi-Query Attention (MQA) | Grouped-Query Attention (GQA) |
| :--- | :--- | :--- | :--- |
| **Query Heads ($h_Q$)** | $h$ | $h$ | $h$ |
| **Key/Value Heads ($h_{KV}$)** | $h$ (Identical to $h_Q$) | **$1$ (Single shared head)** | **$g$ (Grouped heads, e.g., $h / 4$ or $h / 8$)** |
| **KV Cache Size** | **$1.0\times$ (Baseline / Large)**| **$0.125\times$ ($8\times$ smaller)** | **$0.125\times - 0.25\times$ ($4\times-8\times$ smaller)** |
| **Inference Serving Speed** | Lower (Memory bandwidth bottleneck) | Fastest | Near-optimal throughput |
| **Model Expressiveness** | Maximum | Slight perplexity loss | Matches MHA performance |
| **Where Used** | Original Transformer, GPT-3 | PaLM, StarCoder | LLaMA-2/3, Mistral, Gemma 2 |

---

### Key Point

> **Multi-head attention projects queries, keys, and values into parallel subspaces to simultaneously track distinct semantic relationships; modern LLMs employ Grouped-Query Attention (GQA) to preserve this expressiveness while slashing inference KV-cache memory by 8x.**

---

### Interview Answer

> **Multi-Head Attention (MHA) extends the attention mechanism by projecting Queries, Keys, and Values into $h$ separate lower-dimensional subspaces, computing scaled dot-product attention in parallel for each head, concatenating the outputs, and projecting them through an output matrix $\mathbf{W}^O$.
> 
> Because each head operates at dimension $d_k = d_{\text{model}} / h$, MHA introduces zero additional computational overhead compared to a single full-dimensional attention pass. Its primary advantage is representational: different heads specialize in capturing distinct relationships—such as syntactic agreement, long-range coreference, and positional proximity—which would otherwise be averaged into an uninformative blur.
> 
> In modern LLMs (such as LLaMA-3), MHA has been replaced by **Grouped-Query Attention (GQA)**. In GQA, multiple Query heads share a smaller number of Key and Value heads. This reduces the memory footprint of the Key-Value (KV) cache by 4x to 8x during autoregressive decoding, drastically accelerating inference throughput while retaining the representation quality of standard MHA.**
