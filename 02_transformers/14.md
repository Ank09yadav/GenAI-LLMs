## 14. What is positional encoding?

### Answer

Because the self-attention operation is **permutation-invariant** (meaning it treats an unordered bag of words identically to an ordered sentence), a Transformer network has no intrinsic mechanism to understand word order or sequence geometry unless explicit **Positional Encodings** are injected into token representations.

For example, without positional information:
> *"The dog bit the man"* and *"The man bit the dog"*

would produce **identical self-attention matrices and identical final hidden states**, completely reversing the semantic agent and patient of the sentence!

```text
Permutation Invariance of Self-Attention:
Attention(P * X) = P * Attention(X)   (where P is any permutation matrix!)
If you shuffle the input tokens, the output tokens are shuffled in the exact same way.
The network has zero native sense of sequence direction or token distance!

Solution: Positional Encoding (PE)
Token Embedding("dog") + [Positional Signal at Index 1]
Token Embedding("man") + [Positional Signal at Index 4]
Now the network can distinguish word order, grammatical tense, and spatial proximity!
```

### 1. Sinusoidal Absolute Positional Encoding (Vaswani et al., 2017)

In the original Transformer, deterministic trigonometric waves of differing geometric frequencies were added directly to input embeddings:

$$PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i / d_{\text{model}}}}\right)$$
$$PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i / d_{\text{model}}}}\right)$$

where $pos$ is the token position index ($0, 1, 2, \dots, N$) and $i$ is the feature dimension index ($0, 1, \dots, d_{\text{model}} / 2$).

**Why Sine and Cosine?**  
Trigonometric identity enables the model to learn **relative position shifts** through linear transformations:
$$\sin(\alpha + \beta) = \sin \alpha \cos \beta + \cos \alpha \sin \beta$$
$$\cos(\alpha + \beta) = \cos \alpha \cos \beta - \sin \alpha \sin \beta$$
For any fixed offset $k$, $PE_{pos+k}$ can be represented as a linear function of $PE_{pos}$.

---

### 2. Learned Absolute Positional Embeddings (BERT & GPT-2)
Instead of fixed formulas, a lookup matrix $\mathbf{E}_{\text{pos}} \in \mathbb{R}^{L_{\max} \times d_{\text{model}}}$ is initialized randomly and trained via gradient descent.
- **The Fatal Flaw:** The model cannot process sequences longer than $L_{\max}$ without discarding weights or retraining, as position indices beyond $L_{\max}$ have uninitialized embeddings.

---

### 3. Rotary Position Embeddings (RoPE - The Modern Standard)

**RoPE (Rotary Position Embedding)**, introduced by Su et al. (2021), is the undisputed standard in modern LLMs (LLaMA-1/2/3, Mistral, Qwen, DeepSeek, Gemma). 

Instead of *adding* a vector to token embeddings at the input layer, RoPE **multiplies Query and Key vectors by an orthogonal 2D rotation matrix** corresponding to position $m$ inside every attention head:

```text
                     Rotary Position Embedding (RoPE) Mechanics
                     
2D Subspace of Query Vector [q_0, q_1]:
Rotated by angle (m * θ_i) in the complex plane!

       Imaginary Axis
             ▲
             │           Rotated Vector q~_m
             │             ▲
             │            /
             │           /
             │          / ) Angle = m * θ
             │         /
             │        /
             │       ● Original Vector q
             └──────────────────────────────► Real Axis
```

#### The Mathematical Formulation of RoPE
For a 2D chunk of a Query vector at position $m$ with frequency $\theta$:

$$\tilde{\mathbf{q}}_m = \mathbf{R}_{\Theta, m}^d \mathbf{q}_m = \begin{pmatrix} \cos(m\theta) & -\sin(m\theta) \\ \sin(m\theta) & \cos(m\theta) \end{pmatrix} \begin{pmatrix} q_0 \\ q_1 \end{pmatrix}$$

#### The Crucial Relative Invariant Property
When we calculate the attention dot product between a Query at position $m$ and a Key at position $n$:

$$\langle \tilde{\mathbf{q}}_m, \tilde{\mathbf{k}}_n \rangle = \left(\mathbf{R}_{\Theta, m} \mathbf{q}_m\right)^T \left(\mathbf{R}_{\Theta, n} \mathbf{k}_n\right) = \mathbf{q}_m^T \left(\mathbf{R}_{\Theta, m}^T \mathbf{R}_{\Theta, n}\right) \mathbf{k}_n = \mathbf{q}_m^T \mathbf{R}_{\Theta, n-m} \mathbf{k}_n$$

**Notice the exponent:** The dot product depends **strictly on the relative distance $(n - m)$**, rather than absolute coordinates $m$ or $n$!

---

### Context Length Extrapolation with RoPE (NTK-Aware & YaRN)

Because RoPE encodes position as continuous complex rotations, engineers can extend context windows from $8\text{k}$ to $128\text{k}+$ tokens without full pretraining:
- **Linear RoPE Interpolation:** Scales down rotation angles by a factor $s = L_{\text{new}} / L_{\text{old}}$.
- **NTK-Aware Scaling:** Recognizes that high-frequency dimensions encode local grammar (which should not be compressed), while low-frequency dimensions encode long-range context (which can be scaled).
- **YaRN (Yet another RoPE extensioN):** Applies temperature scaling to the attention softmax to preserve entropy balance over massive 128k context windows.

### Key Point

> **Positional encoding breaks the permutation invariance of self-attention; modern LLMs employ Rotary Position Embeddings (RoPE) to encode relative token distances directly into query-key vector rotations, enabling seamless context extrapolation.**

---

### Interview Answer

> **Positional Encoding is required because self-attention is permutation-invariant: without explicit positional indicators, shuffling the tokens in an input sequence yields identical attention weights and hidden states.
> 
> Early architectures used additive methods: either fixed sinusoidal functions or learned absolute lookup tables added to input embeddings. However, absolute methods fail to extrapolate to sequences longer than those seen in training.
> 
> Modern LLMs have converged on **Rotary Position Embedding (RoPE)**. Instead of adding vectors at the input, RoPE rotates the Query and Key vectors in 2D coordinate pairs by an angle proportional to their sequence position $m$. Because the inner product of two rotated vectors depends strictly on their relative distance $(m - n)$, RoPE naturally models relative token dependencies and allows context window expansion (e.g., from 8k to 128k) using frequency-scaling techniques like NTK-Aware and YaRN.**
